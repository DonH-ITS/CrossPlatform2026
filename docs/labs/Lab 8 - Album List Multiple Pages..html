Lab 8: Album List 2 - Navigation, Images and Tabs

Lab 8 - Album Library: Details Page, Images and Tabs

In this lab we continue the album library from Lab 7. The app already downloads a library of albums and displays them in a CollectionView. This week we make it a proper multi-page application.

We will build on it in stages:

  1. Move the HttpClient to the App so the whole application shares one.
  2. Create an AlbumDetailPage that opens when an album is selected, passing the album to it using Shell navigation.
  3. Show the album cover, and find out why most of the covers do not appear at first.
  4. Replace the Library 1 / Library 2 buttons with tabs, so each library gets its own page.
  5. Optional: stretch goals (numbered tracks and layout).
  6. Optional: make the library name editable and have it appear in the tab.
  7. Optional: add and edit albums.
Note

Starting point: the starting code is given in full in the next section. It is the Lab 7 application with the temporary ApiText property and a few small problems already removed.

AlbumViewModel.cs

using System.Collections.ObjectModel;
using System.ComponentModel;
using System.Runtime.CompilerServices;
using System.Text.Json;

namespace AlbumList
{
    public class AlbumViewModel : INotifyPropertyChanged
    {
        private ObservableCollection<Album> _albums = new();
        private string _libraryName = "";
        private bool _isLoading = false;
        private string _errorMessage = "";
        private static readonly HttpClient _httpClient = new HttpClient();
        private const string Library1Url = "https://raw.githubusercontent.com/DonH-ITS/jsonfiles/refs/heads/main/library1.json";
        private const string Library2Url = "https://raw.githubusercontent.com/DonH-ITS/jsonfiles/refs/heads/main/library2.json";
        public Command LoadLibrary1Command { get; }
        public Command LoadLibrary2Command { get; }
        public Command<string> SortCommand { get; }

        public ObservableCollection<Album> Albums
        {
            get => _albums;
            set
            {
                if (_albums != value)
                {
                    _albums = value;
                    OnPropertyChanged();
                }
            }
        }

        public string LibraryName
        {
            get => _libraryName;
            set
            {
                if (_libraryName != value)
                {
                    _libraryName = value;
                    OnPropertyChanged();
                }
            }
        }
        public string ErrorMessage
        {
            get => _errorMessage;
            set
            {
                if (_errorMessage != value)
                {
                    _errorMessage = value;
                    OnPropertyChanged();
                }
            }
        }

        public bool IsLoading
        {
            get => _isLoading;
            set
            {
                if (_isLoading != value)
                {
                    _isLoading = value;
                    OnPropertyChanged();
                }
            }
        }

        public AlbumViewModel()
        {
            LoadLibrary1Command = new Command(async () => await LoadLibraryAsync(Library1Url, "Library 1"));
            LoadLibrary2Command = new Command(async () => await LoadLibraryAsync(Library2Url, "Library 2"));
            SortCommand = new Command<string>(SortAlbums);
        }

        private async Task LoadLibraryAsync(string url, string libraryName)
        {
            IsLoading = true;
            ErrorMessage = "";
            try
            {
                string fileName = Path.Combine(FileSystem.Current.AppDataDirectory, libraryName + ".json");
                // If the cached file exists, use it
                // Probably need to check the library name for invalid characters but fine for now
                if (File.Exists(fileName))
                {
                    string text = await File.ReadAllTextAsync(fileName);
                    Albums = JsonSerializer.Deserialize<ObservableCollection<Album>>(text);
                    LibraryName = libraryName;
                }
                else
                {

                    // Send an HTTP GET request using _httpClient.
                    using var response = await _httpClient.GetAsync(url);
                    // Check that the response was successful.
                    if (response.IsSuccessStatusCode)
                    {
                        string text = await response.Content.ReadAsStringAsync();
                        Albums = JsonSerializer.Deserialize<ObservableCollection<Album>>(text);
                        LibraryName = libraryName;
                        // Cache the file locally
                        await File.WriteAllTextAsync(fileName, text);

                    }

                }

            }
            catch (Exception ex)
            {
                ErrorMessage = ex.Message;
                return;
            }
            finally
            {
                // Finally ALWAYS runs after the others
                IsLoading = false;
            }
        }

        public void SortAlbums(string sortBy)
        {
            switch (sortBy)
            {
                case "Title":
                    Albums = new ObservableCollection<Album>(
                        Albums.OrderBy(a => a.Title));
                    break;

                case "Artist":
                    Albums = new ObservableCollection<Album>(
                        Albums.OrderBy(a => a.Artist));
                    break;

                case "Year":
                    Albums = new ObservableCollection<Album>(
                        Albums.OrderBy(a => a.Year));
                    break;
            }
        }

        public event PropertyChangedEventHandler? PropertyChanged;

        protected void OnPropertyChanged([CallerMemberName] string? propertyName = null)
        {
            PropertyChanged?.Invoke(this, new PropertyChangedEventArgs(propertyName));
        }
    }
}

1. Share One HttpClient

Files to edit, in order:

  1. App.xaml.cs
  2. AlbumViewModel.cs

Currently the AlbumViewModel has its own HttpClient. This week we will have a second page that needs to download an image, and the tabs mean we will have two ViewModels. An application should only ever have one HttpClient, so we are going to move it somewhere everything can reach.

1.1 Create the shared client

Open App.xaml.cs. Add a static property called Http, of type HttpClient, that is created straight away.

A static member belongs to the class itself rather than to an object. That means any page or ViewModel can use it as App.Http, without needing an App object.

TipHint

It is an auto-property with an initialiser, in the same shape as public static Type Name { get; } = new Type();.

TipSolution

Inside the App class:

public static HttpClient Http { get; } = new HttpClient();

1.2 Use it

Open AlbumViewModel.cs. Delete the ViewModel’s own _httpClient field and change LoadLibraryAsync so it uses App.Http instead.

TipSolution

Delete the _httpClient field, then change the request line to:

using var response = await App.Http.GetAsync(url);
Note

The starter caches the downloaded JSON, so if you have already run the app the download is skipped and your change is not actually being used. To check it, set a breakpoint on the App.Http.GetAsync line. If it is never hit, find the cached file by printing FileSystem.Current.AppDataDirectory with Debug.WriteLine, and delete the .json files in that folder.

Run the app and make sure both libraries still download.

2.2 Receive the album

The details page needs to be given an album by whichever page navigates to it. Shell does this with navigation parameters, which have two ends:

  • The sender puts values in a Dictionary and passes it to GoToAsync. We will write this in section 2.6.
  • The receiver says which values it wants, using a [QueryProperty] attribute. Shell copies each value into a property of the page.

The album arrives after the page’s constructor has finished, so the constructor is too early to use it. The page has to wait until it appears.

Replace the contents of AlbumDetailPage.xaml.cs with this skeleton and complete the four TODOs:

    }

    private async void Button_Clicked(object sender, EventArgs e)
    {

TipHint 1: the attribute

The attribute goes directly above the class. It takes two values: the name of the property to copy into (use nameof(...)), and the key that the sender will use. We will use the key "Album".

[QueryProperty(nameof(PropertyName), "Key")]
TipHint 2: appearing and going back

Override OnAppearing. It is async void, and should call base.OnAppearing() first. Then wait a moment with await Task.Delay(50); and set BindingContext.

To go back, use await Shell.Current.GoToAsync("..");. The two dots mean “back one page”.

TipSolution

TipHint

Use Routing.RegisterRoute. It takes the route (a string) and the type of the page. nameof(AlbumDetailPage) gives you the string "AlbumDetailPage", and typeof(AlbumDetailPage) gives you the type.

2.5 Make the list selectable

Open MainPage.xaml and find the CollectionView. Change it so that:

  • the user can select one item at a time (SelectionMode)
  • the selected item is bound to the ViewModel’s SelectedAlbum (SelectedItem)
  • a method is called when the selection changes (SelectionChanged). Let Visual Studio create the handler for you: type = after the event name and choose New Event Handler.
TipHint

By default a CollectionView has selection turned off. The three properties are SelectionMode, SelectedItem and SelectionChanged. Name your handler CollectionView_SelectionChanged.

TipSolution 
<CollectionView Grid.Row="4"
                ItemsSource="{Binding Albums}"
                SelectionMode="Single"
                SelectedItem="{Binding SelectedAlbum}"
                SelectionChanged="CollectionView_SelectionChanged">

SelectedItem="{Binding SelectedAlbum}" keeps the ViewModel’s SelectedAlbum in step with whatever is selected. We will not actually use SelectedAlbum to navigate, because the event gives us the album directly. It shows that a selection can be bound just like any other property.

2.6 Navigate with parameters

Now for the sender. Open MainPage.xaml.cs. The handler needs to do four things:

private async void CollectionView_SelectionChanged(object sender, SelectionChangedEventArgs e)
{
    // 1. Get the selected album from e.CurrentSelection, if there is one
    // 2. Put it in a Dictionary<string, object> using the key "Album"
    // 3. Navigate to AlbumDetailPage, sending the dictionary
    // 4. Clear the selection
}

In the lectures you have used GoToAsync to go to a page. This time we are also sending data to the page, as a Dictionary of keys and values. The key must match the one in the receiving page’s [QueryProperty], and the value is the object we want to send.

TipHint for step 1

e.CurrentSelection is a list of the selected items. FirstOrDefault() gives the first one, or null if the list is empty. The is pattern checks the type and gives the object a name in one go:

if (e.CurrentSelection.FirstOrDefault() is Album selectedAlbum)
{
    ...
}
TipHint for steps 2 and 3

A dictionary can be filled when it is created:

var parameters = new Dictionary<string, object>
{
    { "key", value }
};

GoToAsync has a version that takes the dictionary as a second parameter after the route. The route is nameof(AlbumDetailPage).

TipHint for step 4

sender is the CollectionView that raised the event, but it is typed as object, so it has to be cast: ((CollectionView)sender).SelectedItem = null;

TipSolution 
private async void CollectionView_SelectionChanged(object sender, SelectionChangedEventArgs e)
{
    if (e.CurrentSelection.FirstOrDefault() is Album selectedAlbum)
    {
        var parameters = new Dictionary<string, object>
        {
            { "Album", selectedAlbum }
        };

        await Shell.Current.GoToAsync(nameof(AlbumDetailPage), parameters);
        ((CollectionView)sender).SelectedItem = null;
    }
}

Run the application. Selecting an album should open the details page, showing the album information and its track list. The Back button should return you to the list.

Make sure you understand these points:

  • The value in the dictionary is the same Album object, not a copy.
  • At the end we set SelectedItem = null. If we did not, the album would stay highlighted, and tapping it again after coming back would do nothing, because the selection would not have changed.
  • Setting SelectedItem = null is itself a change, so SelectionChanged fires a second time. That time CurrentSelection is empty, so is Album is false and the method does nothing.

3. Showing the Album Cover

Files to edit, in order:

  1. AlbumDetailPage.xaml
  2. App.xaml.cs
  3. AlbumDetailPage.xaml.cs
  4. AlbumDetailPage.xaml

Every album has a CoverUrl. Let’s show the cover on the details page.

3.1 The obvious way

The details page already has an Image control, but nothing is set as its source. In AlbumDetailPage.xaml, make the Image show the album’s CoverUrl.

TipHint

An Image can take a URL as its Source. Bind it.

TipSolution 
<Image x:Name="ImageDisplay"
       Source="{Binding CoverUrl}"
       HeightRequest="180" WidthRequest="180" Aspect="AspectFit" />

Run the application and open several albums.

You should find that the cover for Kills Birds appears, but the covers for the other albums are blank. There is no error message at all.

3.2 Why?

Most of these covers are hosted on Wikipedia. Wikipedia only serves images to requests that identify themselves with a user-agent header. A user-agent is what a browser sends with every request to say who is asking (see the MDN page on User-Agent). Wikipedia does not care what the agent says, only that there is one.

The Image control does not send a user-agent, so Wikipedia refuses and we get a blank image. The Kills Birds cover is not served from Wikipedia, so it works without one.

This is not a bug in our code or in MAUI. The fix is to download the image ourselves, using the shared HttpClient, with a user-agent set.

3.3 Set a user-agent on the shared HttpClient

Open App.xaml.cs and add a line to the App constructor, after InitializeComponent():

Http.DefaultRequestHeaders.UserAgent.ParseAdd("MyMauiApp/1.0");

DefaultRequestHeaders are headers added to every request made with this client. This is the reason we wanted a single shared HttpClient: the header is set once, in one place. It will also be sent when we download the JSON libraries, which is harmless.

3.4 Download the image ourselves

Go back to AlbumDetailPage.xaml and remove the Source="{Binding CoverUrl}" from the Image. We will set the source from code instead.

In AlbumDetailPage.xaml.cs, change OnAppearing so that after setting the BindingContext it:

  1. downloads the image as an array of bytes, using the shared HttpClient
  2. turns those bytes into something an Image can display
  3. gives that to ImageDisplay
  4. does all of the above inside a try and catch, because downloading can fail (what if there is no connection?). If it fails, give the image a black background so the user can see something went wrong.
TipHint for step 1

HttpClient has a method that returns the response body as a byte[]: GetByteArrayAsync(url). Remember to await it. The URL is the album’s CoverUrl.

TipHint for steps 2 and 3

ImageSource.FromStream(...) creates an image source. It takes a function that returns a Stream, so give it a lambda: () => new MemoryStream(data). A MemoryStream is a stream over bytes that are already in memory. Assign the result to ImageDisplay.Source.

TipSolution 
protected override async void OnAppearing()
{
    base.OnAppearing();
    await Task.Delay(50);
    BindingContext = AlbumProperty;

    try
    {
        byte[] data = await App.Http.GetByteArrayAsync(AlbumProperty.CoverUrl);
        ImageDisplay.Source = ImageSource.FromStream(() => new MemoryStream(data));
    }
    catch (Exception)
    {
        ImageDisplay.BackgroundColor = Colors.Black;
    }
}

Run the application. Every album should now show its cover, after a short delay.

3.5 Show an activity indicator

The image takes a moment to appear, so let’s show an ActivityIndicator while it downloads. This time the property to bind to is on the page itself, not on the Album.

In the code behind

  • Add a bool property IsDownloading to the page that raises PropertyChanged when it changes.
  • Add a get-only property IsNotDownloading that is always the opposite. The UI also has to be told when it changes, so the IsDownloading setter should raise PropertyChanged for both.
  • In OnAppearing, set IsDownloading to true before the download and back to false when it finishes, whether it worked or not.
Note

In the ViewModel we implemented INotifyPropertyChanged ourselves. We do not need to here, because a ContentPage already provides OnPropertyChanged.

TipHint

Things that always run, whether or not there was an exception, belong in a finally block. OnPropertyChanged(nameof(IsNotDownloading)) raises the notification for another property.

TipSolution

Add inside the class:

private bool _isDownloading = false;
private bool _hasImage = false;

public bool IsDownloading
{
    get => _isDownloading;
    set
    {
        if (_isDownloading != value)
        {
            _isDownloading = value;
            OnPropertyChanged();
            OnPropertyChanged(nameof(IsNotDownloading));
        }
    }
}

public bool IsNotDownloading => !IsDownloading;

and replace OnAppearing:

protected override async void OnAppearing()
{
    base.OnAppearing();
    await Task.Delay(50);

    if (!_hasImage)
    {
        BindingContext = AlbumProperty;
        IsDownloading = true;

        try
        {
            byte[] data = await App.Http.GetByteArrayAsync(AlbumProperty.CoverUrl);
            ImageDisplay.Source = ImageSource.FromStream(() => new MemoryStream(data));
            _hasImage = true;
        }
        catch (Exception)
        {
            ImageDisplay.BackgroundColor = Colors.Black;
        }
        finally
        {
            IsDownloading = false;
        }
    }
}

_hasImage stops the image being downloaded again if the page appears a second time. It is only set once the download has worked, so a failed download will be tried again.

In the XAML

Add an ActivityIndicator above the Image, and make the Image hide while downloading. Both need to bind to the properties on the page, not the album.

TipHint

A binding normally looks for its property on the BindingContext, which is the Album. Adding Source= to a binding gives it somewhere else to look. {x:Reference AlbDetail} refers to the element with that x:Name, which is our page. You have seen binding one element to another before.

The ActivityIndicator needs IsRunning and IsVisible bound to IsDownloading. The Image needs IsVisible bound to IsNotDownloading.

TipSolution 
<ActivityIndicator IsVisible="{Binding IsDownloading, Source={x:Reference AlbDetail}}"
                   IsRunning="{Binding IsDownloading, Source={x:Reference AlbDetail}}"
                   VerticalOptions="Center"
                   HorizontalOptions="Center"
                   HeightRequest="180" WidthRequest="180" />
<Image x:Name="ImageDisplay"
       IsVisible="{Binding IsNotDownloading, Source={x:Reference AlbDetail}}"
       HeightRequest="180" WidthRequest="180" Aspect="AspectFit" />

Run the application again. Every album should show its cover, with a spinner while it loads.

TipHint

A failed response is the else of if (response.IsSuccessStatusCode). response.StatusCode tells you what went wrong.

TipSolution 
public bool IsLoaded { get; private set; } = false;

public async Task DownloadAlbums()
{
    IsLoading = true;
    ErrorMessage = "";
    try
    {
        string fileName = Path.Combine(FileSystem.Current.AppDataDirectory, $"library{_libraryNo}.json");
        // If the cached file exists, use it
        if (File.Exists(fileName))
        {
            string text = await File.ReadAllTextAsync(fileName);
            Albums = JsonSerializer.Deserialize<ObservableCollection<Album>>(text);
            IsLoaded = true;
        }
        else
        {
            using var response = await App.Http.GetAsync(_url);
            if (response.IsSuccessStatusCode)
            {
                string text = await response.Content.ReadAsStringAsync();
                Albums = JsonSerializer.Deserialize<ObservableCollection<Album>>(text);
                // Cache the file locally
                await File.WriteAllTextAsync(fileName, text);
                IsLoaded = true;
            }
            else
            {
                ErrorMessage = $"Download failed: {response.StatusCode}";
            }
        }
    }
    catch (Exception ex)
    {
        ErrorMessage = ex.Message;
        return;
    }
    finally
    {
        // Finally ALWAYS runs after the others
        IsLoading = false;
    }
}
Note

The return in the catch block does not stop the finally block from running. IsLoading is still set back to false.

6.1 Number the tracks

At the moment the details page shows the tracks as a plain list. Change it so that each track shows its position in the album: “1. First Track”, “2. Second Track”, and so on.

TipHint 1: Where do the numbers come from?

The numbers are not in the JSON, so something has to build strings like "1. Intro" from the track names.

Rather than changing Tracks (which holds the real track names), add a new get-only property to the Album class that works out the numbered strings from Tracks. Then bind the CollectionView on the details page to your new property instead of Tracks.

You have already written a get-only property in this lab: public bool IsNotDownloading => !IsDownloading;. Yours will have the same shape, but its type is IEnumerable<string>.

TipHint 2: Putting a number in front of each track

LINQ’s Select builds a new list from an existing one by running some code on every item. There is a version of Select that gives you the position of each item as well as the item itself:

Tracks.Select((track, index) => ...)

Inside, build the new string with string interpolation ($"..."). Remember that the index starts at 0, but track numbers start at 1.

TipHint 3: Solution

Add this property to Album.cs:

public IEnumerable<string> NumberedTracks => Tracks.Select((t, i) => $"{i + 1}. {t}");

Then in AlbumDetailPage.xaml change the CollectionView’s binding:

<CollectionView Grid.Row="1" ItemsSource="{Binding NumberedTracks}">

The tracks do not change while the page is open, so there is no need to raise PropertyChanged.

6.2 Adapt the layout

On Windows the details page looks better with the album information on the left and the track list on the right. On a narrow screen (an Android phone, or a Windows window that has been resized) the current stacked layout is better. Make the page switch between the two layouts depending on how wide it is, including when the window is resized.

TipHint 1: Where should the decision be made?

The outer Grid on the page currently has two rows. Side by side needs two columns instead.

Whether the page is wide or narrow can change while the app is running (the user can resize the window), so you cannot decide it once in XAML. It has to be decided in code, every time the page’s size changes.

TipHint 2: The tools you need
  • A page has an OnSizeAllocated(double width, double height) method you can override. It runs whenever the page’s size changes.
  • Give the outer Grid and the two things inside it an x:Name in the XAML (MainGrid, DetailsStack and TracksGrid), so that you can use them from code.
  • A Grid’s layout can be changed from code: MainGrid.RowDefinitions.Clear(), MainGrid.ColumnDefinitions.Add(new ColumnDefinition(...)), and Grid.SetRow(view, n) / Grid.SetColumn(view, n) to move a control to a cell.
  • Pick a width to count as “wide”. Around 700 works well.
  • Rearranging the grid every time the size changes by a few pixels is wasteful. Remember whether the page was wide last time, and only rearrange when that changes.
TipHint 3: Solution

In AlbumDetailPage.xaml, add the names (leave everything else as it is):

<Grid x:Name="MainGrid" Padding="15" RowSpacing="10" RowDefinitions="Auto,*">
    <VerticalStackLayout x:Name="DetailsStack" Grid.Row="0" Spacing="10">
<Grid x:Name="TracksGrid" Grid.Row="1" RowDefinitions="Auto,*" RowSpacing="10">

Then add this to AlbumDetailPage.xaml.cs:

private bool? _isWide;

protected override void OnSizeAllocated(double width, double height)
{
    base.OnSizeAllocated(width, height);

    bool isWide = width > 700;
    if (isWide == _isWide)
    {
        return;
    }
    _isWide = isWide;

    MainGrid.RowDefinitions.Clear();
    MainGrid.ColumnDefinitions.Clear();

    if (isWide)
    {
        MainGrid.ColumnDefinitions.Add(new ColumnDefinition(new GridLength(1, GridUnitType.Star)));
        MainGrid.ColumnDefinitions.Add(new ColumnDefinition(new GridLength(2, GridUnitType.Star)));
        Grid.SetRow(DetailsStack, 0);
        Grid.SetColumn(DetailsStack, 0);
        Grid.SetRow(TracksGrid, 0);
        Grid.SetColumn(TracksGrid, 1);
    }
    else
    {
        MainGrid.RowDefinitions.Add(new RowDefinition(GridLength.Auto));
        MainGrid.RowDefinitions.Add(new RowDefinition(GridLength.Star));
        Grid.SetRow(DetailsStack, 0);
        Grid.SetColumn(DetailsStack, 0);
        Grid.SetRow(TracksGrid, 1);
        Grid.SetColumn(TracksGrid, 0);
    }
}

8.1 Saving

Changes need to be saved, or they will be lost when the app is restarted (it reads the cached file at startup).

Note

If you did the “Number the tracks” stretch goal, your NumberedTracks property is worked out from Tracks, so it should not be written into the saved file. Add [JsonIgnore] on the line above it in Album.cs, and using System.Text.Json.Serialization; at the top of the file.

In AlbumViewModel.cs, write three methods:

  • SaveLibrary() writes the current Albums to the library’s cache file, the one that DownloadAlbums reads.
  • AddAlbum(Album album) adds an album and saves.
  • ReplaceAlbum(Album oldAlbum, Album newAlbum) puts newAlbum in the same position as oldAlbum, and saves.

Why replace, rather than change the old album’s properties? Album does not raise PropertyChanged, so changing a property would not update the list. Putting a new item into an ObservableCollection is something the collection announces, so the CollectionView updates.

TipHint

JsonSerializer.Serialize(Albums) turns the collection into JSON text, and File.WriteAllTextAsync(fileName, json) writes it, the reverse of what DownloadAlbums does. Albums.IndexOf(oldAlbum) finds a position, and Albums[index] = newAlbum replaces the item there.

TipSolution 
public async Task SaveLibrary()
{
    string fileName = Path.Combine(FileSystem.Current.AppDataDirectory, $"library{_libraryNo}.json");
    string json = JsonSerializer.Serialize(Albums);
    await File.WriteAllTextAsync(fileName, json);
}

public async Task AddAlbum(Album album)
{
    Albums.Add(album);
    await SaveLibrary();
}

public async Task ReplaceAlbum(Album oldAlbum, Album newAlbum)
{
    int index = Albums.IndexOf(oldAlbum);
    if (index >= 0)
    {
        Albums[index] = newAlbum;
        await SaveLibrary();
    }
}

            Artist = ArtistEntry.Text,
