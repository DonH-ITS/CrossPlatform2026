Lab 7: Album List 1 - Downloading via API and ObservableCollections

Lab 7 - Album Library: Downloading Data from an API

In this lab, we will build an application that downloads album information from an online API and displays it in a collection.

We will build the application in stages:

  1. Generate a C# class to represent an album using example JSON data.
  2. Create a ViewModel to manage the album data.
  3. Build the initial page layout, including a temporary area to display the downloaded JSON.
  4. Connect the ViewModel to the page.
  5. Download JSON data from an API and display it.
  6. Create commands to load two different libraries and test the download.
  7. Deserialise the JSON into an ObservableCollection<Album>.
  8. Display the albums using a CollectionView.
  9. Add sorting.

2. Generate the Album Class

File to edit: Album.cs

Rather than writing the C# class ourselves, we are going to generate it from an example of the JSON data.

Open the following website:

https://json2csharp.com/

We will use the first library as our example:

https://raw.githubusercontent.com/DonH-ITS/jsonfiles/refs/heads/main/library1.json

  1. Open the JSON URL in your browser.
  2. Copy the JSON contents.
  3. Paste the contents into the JSON input on the conversion website.
  4. Set the class name to Album.
  5. Generate the C# classes.

You should end up with a class representing an album.

The JSON contains the following properties:

Property Data type
Title string
Artist string
Year int
Genre string
CoverUrl string
Tracks List of strings

Notice that Tracks is an array of strings in the JSON. The generated C# class should represent this as a collection of strings.

Copy the generated class into a new file called Album.cs. Don’t forget to leave your namespace alone.

Important: Both JSON libraries use the same structure, so we only need one Album class.

3. Create the ViewModel

File to edit: AlbumViewModel.cs

Create a new class called AlbumViewModel.

This class will manage the album data and the operations required by the application.

The ViewModel will need the following properties:

Property Type Purpose
Albums ObservableCollection<Album> Holds the albums displayed by the application
LibraryName string The name of the currently loaded library
IsLoading bool Indicates whether data is currently being downloaded
ErrorMessage string Holds any error message
ApiText string Temporarily holds the downloaded JSON text

Each property should have a private backing field and a setter that calls OnPropertyChanged() when its value changes.

This is important because we will be replacing the entire Albums collection when loading and sorting the data, rather than simply modifying its contents.

Note

Don’t forget to make a constructor, empty for now

Implement INotifyPropertyChanged

The ViewModel needs to implement INotifyPropertyChanged so that the user interface is updated when its properties change.

Add the interface to your class:

public class AlbumViewModel : INotifyPropertyChanged
{
    public event PropertyChangedEventHandler PropertyChanged;

    // Properties and other code will go here.
}

Add the following method inside the class:

private void OnPropertyChanged(
    [System.Runtime.CompilerServices.CallerMemberName] string propertyName = "")
{
    PropertyChanged?.Invoke(
        this, new PropertyChangedEventArgs(propertyName));
}

You can now create the properties listed above.

Remember that each property needs a backing field and should call OnPropertyChanged() in its setter.

For example, your Albums property will look something like this:

private ObservableCollection<Album> _albums = new();

public ObservableCollection<Album> Albums
{
    get => _albums;
    set
    {
        _albums = value;
        OnPropertyChanged();
    }
}

Create the remaining properties in a similar way.

5. Connect the ViewModel to the Page

File to edit: MainPage.xaml.cs

We now need to connect the ViewModel to the page.

Open MainPage.xaml.cs.

Add a field to hold an instance of the ViewModel:

private AlbumViewModel _viewModel;

In the constructor, create the ViewModel and assign it to the page’s BindingContext:

public MainPage()
{
    InitializeComponent();

    _viewModel = new AlbumViewModel();
    BindingContext = _viewModel;
}

The BindingContext connects the XAML page to the ViewModel.

For example, the label we created earlier has:

Text="{Binding LibraryName}"

This means that its Text property is connected to the LibraryName property in the ViewModel.

When LibraryName changes and PropertyChanged is raised, the label will update automatically.

6. Download the JSON Data

File to edit: AlbumViewModel.cs

We will use HttpClient to download the JSON data from the online libraries.

First, add an HttpClient field to the ViewModel:

private static readonly HttpClient _httpClient = new HttpClient();

For this lab, a single static HttpClient instance in the ViewModel is sufficient. In a larger application, the HTTP client would normally be shared more widely.

Now create an asynchronous method called LoadLibraryAsync.

It should accept two parameters:

  • url: the address of the JSON file.
  • libraryName: the name of the library being loaded.

Start with the following structure:

private async Task LoadLibraryAsync(string url, string libraryName)
{
    IsLoading = true;
    ErrorMessage = "";
    ApiText = "";

    try
    {
        // Send an HTTP GET request using _httpClient.

        // Check that the response was successful.

        // Read the response content as a string.

        // Assign the downloaded JSON to ApiText.
    }
    catch (Exception ex)
    {
        ErrorMessage = ex.Message;
    }
    finally
    {
        IsLoading = false;
    }
}

Complete the four steps inside the try block. The following hints should help.

Step What you need to do Method or variable to use
1 Send a request to the URL and store the response. HttpResponseMessage and _httpClient.GetAsync(url)
2 Check that the HTTP request was successful. EnsureSuccessStatusCode()
3 Read the response body and store it as a string called json. ReadAsStringAsync()
4 Assign the downloaded JSON to the ApiText property. ApiText = json

A few things to remember:

  • Both GetAsync() and ReadAsStringAsync() are asynchronous methods, so you will need to use await.
  • The response from GetAsync() should be stored in a variable so that you can use it in the following steps.
  • The JSON itself should be stored in a string variable called json.
  • EnsureSuccessStatusCode() checks the response and throws an exception if the request was unsuccessful. Our catch block will handle this.

Why are we using async and await?

Downloading data involves communicating with another computer over the internet. This can take some time.

Using async and await allows the application to wait for the download without freezing the user interface.

When the JSON has been downloaded, assign it to ApiText.

Because ApiText raises PropertyChanged, the label on the page should update automatically.

7. Create the Library Commands and Test the Download

Files to edit, in order:

  1. AlbumViewModel.cs
  2. MainPage.xaml

We now need a way for the user to select which library to download.

7.1 Create the commands

7.1 Create the commands

In AlbumViewModel.cs, create two commands:

public Command LoadLibrary1Command { get; }
public Command LoadLibrary2Command { get; }

A command runs a method with no parameters, but LoadLibraryAsync needs a URL and a library name. We solve this with a lambda (anonymous method). The lambda is a small unnamed method that calls LoadLibraryAsync with the details we want.

In the ViewModel constructor, initialise the first command:

LoadLibrary1Command = new Command(
    async () => await LoadLibraryAsync(Library1Url, "Library 1"));

Because LoadLibraryAsync is asynchronous, the lambda is marked async and uses await.

Initialise LoadLibrary2Command yourself in the same way, using Library2Url and the name “Library 2”.

Here are constants for the two URLs:

private const string Library1Url =
    "https://raw.githubusercontent.com/DonH-ITS/jsonfiles/refs/heads/main/library1.json";

private const string Library2Url =
    "https://raw.githubusercontent.com/DonH-ITS/jsonfiles/refs/heads/main/library2.json";

7.2 Connect the buttons

Open MainPage.xaml.

Update the two library buttons so that they use the commands:

<Button Text="Library 1"
        Command="{Binding LoadLibrary1Command}"/>

<Button Text="Library 2"
        Command="{Binding LoadLibrary2Command}"/>

7.3 Connect the loading indicator and error message

The ActivityIndicator should run while IsLoading is true.

Update it to:

<ActivityIndicator IsRunning="{Binding IsLoading}"
                   IsVisible="{Binding IsLoading}"/>

Update the error label:

<Label Text="{Binding ErrorMessage}"
       TextColor="Red"
       HorizontalOptions="Center"/>

7.4 Test the download

Run the application.

Press the Library 1 button. You should see the JSON contents displayed in the temporary area at the bottom of the page.

Try pressing the Library 2 button.

Check that:

  • The JSON contents change.
  • The library name is displayed.
  • The ActivityIndicator appears while downloading.
  • An error message is displayed if the download fails.

At this stage, we have successfully downloaded the JSON data, but we are still displaying it as plain text.

Next, we will convert it into C# objects.

8. Deserialise the JSON into Albums

File to edit: AlbumViewModel.cs

We now have the JSON data stored in ApiText.

Instead of displaying the JSON as text, we want to convert it into a collection of Album objects.

This process is called deserialisation.

We will use System.Text.Json to do this.

Inside LoadLibraryAsync(), immediately after:

ApiText = json;

add:

Albums = JsonSerializer.Deserialize<ObservableCollection<Album>>(json);

LibraryName = libraryName;

You may need to add the System.Text.Json namespace. If Visual Studio identifies an unknown type, use its Quick Actions to add the required namespace.

The Deserialize method converts the JSON text into an ObservableCollection<Album>.

We can now access individual albums through the Albums property.

Why use ObservableCollection?

An ObservableCollection notifies the user interface when items are added or removed. This is useful when displaying collections of data in controls such as a CollectionView.

Our Albums property already has a setter that raises PropertyChanged. This is also important here because we are replacing the collection with a newly deserialised collection.

For now, the raw JSON will still be displayed on the page. We will replace that temporary display in the next section.

9. Display Albums Using a CollectionView

File to edit: MainPage.xaml

We now have a collection of Album objects. We want to display these in a CollectionView.

Open MainPage.xaml.

9.1 Add the CollectionView

Find the temporary ScrollView and Label that display the JSON.

Remove them and replace them with:

<CollectionView Grid.Row="4"
                ItemsSource="{Binding Albums}">
</CollectionView>

The ItemsSource property connects the CollectionView to the Albums collection in the ViewModel.

9.2 Add an ItemTemplate

A CollectionView needs to know how each item should be displayed.

Add an ItemTemplate inside the CollectionView:

<CollectionView.ItemTemplate>
    <DataTemplate>

    </DataTemplate>
</CollectionView.ItemTemplate>

The DataTemplate describes how to display one item in the collection.

The CollectionView will repeat this template for every album.

9.3 Display the album information

Inside the DataTemplate, add a VerticalStackLayout containing labels for the album properties.

Your completed CollectionView should look like this:

<CollectionView Grid.Row="4"
                ItemsSource="{Binding Albums}">
    <CollectionView.ItemTemplate>
        <DataTemplate>
            <VerticalStackLayout Padding="10">
                <Label Text="{Binding Title}"
                       FontSize="Medium"
                       FontAttributes="Bold"/>

                <Label Text="{Binding Artist}"
                       FontSize="Small"/>

                <Label Text="{Binding Year}"
                       FontSize="Small"/>

                <Label Text="{Binding Genre}"
                       FontSize="Small"/>
            </VerticalStackLayout>
        </DataTemplate>
    </CollectionView.ItemTemplate>
</CollectionView>

Notice that the bindings inside the DataTemplate refer directly to Title, Artist, Year and Genre.

This is because the binding context inside the template is an individual Album object, rather than the ViewModel.

9.4 Test the CollectionView

Run the application again.

You should now see the albums displayed as individual items in the CollectionView.

The CollectionView handles its own scrolling, so we do not need to place it inside a ScrollView.

The * in the Grid row definition allows the CollectionView to occupy the remaining available space.

10. Add Sorting

Files to edit, in order:

  1. AlbumViewModel.cs
  2. MainPage.xaml

We will now add the ability to sort the albums by title, artist or year.

10.1 Create the sorting method

In AlbumViewModel.cs, add the following method:

public void SortAlbums(string sortBy)
{
    switch (sortBy)
    {
        case "Title":
            Albums = new ObservableCollection<Album>(
                Albums.OrderBy(a => a.Title));
            break;

        case "Artist":
            Albums = new ObservableCollection<Album>(
                Albums.OrderBy(a => a.Artist));
            break;

        case "Year":
            Albums = new ObservableCollection<Album>(
                Albums.OrderBy(a => a.Year));
            break;
    }
}

This method creates a new collection containing the albums in the requested order.

We are using OrderBy() to perform the sorting. You do not need to understand the details of this method for this lab.

10.2 Create the sorting command

Add a command property to the ViewModel:

public Command<string> SortCommand { get; }

In the constructor, initialise it:

SortCommand = new Command<string>(SortAlbums);

This command accepts a string parameter and passes it to the SortAlbums method.

10.3 Connect the sorting buttons

Open MainPage.xaml.

Update the three sorting buttons:

<Button Text="Title"
        Command="{Binding SortCommand}"
        CommandParameter="Title"/>

<Button Text="Artist"
        Command="{Binding SortCommand}"
        CommandParameter="Artist"/>

<Button Text="Year"
        Command="{Binding SortCommand}"
        CommandParameter="Year"/>

All three buttons use the same command.

The CommandParameter tells the method which property to sort by.

Run the application and test all three sorting options.

11. Optional: Compiled Bindings

File to edit: MainPage.xaml

MAUI supports compiled bindings, which allow binding expressions to be checked at compile time.

To use compiled bindings, we need to tell MAUI what type of object the page and its templates are working with.

First, add a namespace declaration to the opening ContentPage element:

xmlns:local="clr-namespace:AlbumList"

Then add:

x:DataType="local:AlbumViewModel"

The opening element should now look like this:

<ContentPage xmlns="http://schemas.microsoft.com/dotnet/2021/maui"
             xmlns:x="http://schemas.microsoft.com/winfx/2009/xaml"
             xmlns:local="clr-namespace:AlbumList"
             x:Class="AlbumList.MainPage"
             x:DataType="local:AlbumViewModel"
             Title="Album Library">

The page’s binding context is the AlbumViewModel.

However, inside the CollectionView’s DataTemplate, the binding context is an individual Album.

Add the following to the DataTemplate:

<DataTemplate x:DataType="local:Album">

This tells MAUI that the bindings inside the template refer to an Album object.

12. Final Checks

Your application should now be able to:

  • Download Library 1.
  • Download Library 2.
  • Display the albums in a CollectionView.
  • Sort the albums by title.
  • Sort the albums by artist.
  • Sort the albums by year.
  • Display a loading indicator while downloading.
  • Display an error message if something goes wrong.

You can now remove the temporary ApiText property and the code used to display the raw JSON.

Extension: Cache the Downloaded JSON

At the moment, the application downloads the JSON every time a library is selected.

As an extension, investigate how you could save the downloaded JSON to a local file so that it can be reused later.

You can use:

  • FileSystem.Current.AppDataDirectory to obtain the application’s data directory.
  • File.WriteAllTextAsync() to save the downloaded JSON to a file.

This would allow the application to retain a local copy of the library rather than needing to download it every time.
