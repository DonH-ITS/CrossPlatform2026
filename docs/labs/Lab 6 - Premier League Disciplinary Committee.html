Lab 6: Disciplinary Committee

Aim

The Premier League has asked you to join its newly formed Disciplinary Committee. Your job is to review the league table and issue points deductions or awards to clubs when you feel they deserve them.

You will build a small .NET MAUI application that:

  • Loads the original Premier League table from a JSON file in Resources/Raw.
  • Displays the league table.
  • Allows you to enter disciplinary decisions for clubs.
  • Recalculates and displays the table after decisions are applied.
  • Saves and loads your disciplinary decisions as JSON.
  • Uses XAML resources (StaticResource and DynamicResource) to style the application.
  • Includes a small example of data binding on MainPage.

You will bring together several of the topics covered so far:

  • Serialising and deserialising objects using JSON.
  • Reading a file that is packaged with the application.
  • Reading and writing a file in the application’s data folder.
  • Using XAML resources.
  • A first look at data binding.

You will be given a lot of the code, but you will need to complete and connect the different parts.

Work through the lab in order. Get each part working before moving on to the next one.

This lab is designed to be finished in a single session of about two hours. Anything marked Optional (and the stretch goals at the end) can be skipped if you are short of time.

The supplied league table is a fixed snapshot of the 2026/27 Premier League table as of 8 November 2026. It is not intended to update automatically.

1. Create the Project

Create a new .NET MAUI App project called PremierLeagueCommittee.

Most of your code for this lab will be in MainPage.xaml and MainPage.xaml.cs. You will also add three small class files in Section 3.

Make sure the template project runs before doing any modifications.

Add the league data

The league table is supplied as a file called premierleague.json (it’s on Moodle). Add it to the Resources/Raw folder of your project. Drag and drop it onto the folder in Solution Explorer. Do not put it in the root of the project, or the application won’t be able to find it.

The file is a JSON array containing one object for each club. It looks like this (these are example values, not real ones):

[
  {
    "Name": "Example Town",
    "Played": 11,
    "Won": 6,
    "Drawn": 3,
    "Lost": 2,
    "GoalDifference": 8,
    "Points": 21
  }
]

The property names in the file are exactly the same as the property names of the Team class that is supplied later in this lab. This matters, because System.Text.Json is case-sensitive by default. If your table later loads with blank club names and zeros everywhere, and you get no error message, a mismatch between the JSON names and the C# property names is the first thing to check.

The file contains the original league table. It is supplied as part of the application and should not be changed by your application.

Files in Resources/Raw are packaged inside the application. You can read them, but they are not ordinary files that you can edit in place. Think about this: if the application cannot write to Resources/Raw, where will it save the committee’s decisions? You will find out in Section 9.

3. The Data Classes and MainPage.xaml.cs

The data classes

In C#, each class normally lives in its own file. The application uses three simple classes to hold its data. Create each one in its own file:

  1. Right-click the project in Solution Explorer and choose Add > Class…
  2. Give the file the name shown below (Team.cs, DisciplinaryRecord.cs and CommitteeData.cs).
  3. Delete everything in the new file and paste in the code shown.

The namespace line in each file must match your project’s namespace. If you did not call your project PremierLeagueCommittee, change it.

Team holds one row of the league table. AdjustedPoints is calculated by the application and is not stored in premierleague.json, so it is marked with [JsonIgnore].

Team.cs:

using System.Text.Json.Serialization;

namespace PremierLeagueCommittee;

public class Team
{
    public string Name { get; set; } = "";
    public int Played { get; set; }
    public int Won { get; set; }
    public int Drawn { get; set; }
    public int Lost { get; set; }
    public int GoalDifference { get; set; }
    public int Points { get; set; }

    // This value is calculated and is not stored in premierleague.json.
    [JsonIgnore]
    public int AdjustedPoints { get; set; }
}

    // Returns the team with the given name (ignoring upper and lower case),
    // or null if there is no such team.
    private Team? FindTeam(string name)
    {
        foreach (Team team in _teams)
        {
            if (string.Equals(team.Name, name, StringComparison.OrdinalIgnoreCase))
            {
                return team;
            }

        return null;

    private void ClearDecisions_Clicked(object sender, EventArgs e)

    private void CalculateTable()
    {
        // Reset adjusted points to the original points.
        foreach (Team team in _teams)
        {
            team.AdjustedPoints = team.Points;
        }

        // Apply every disciplinary decision.
        foreach (DisciplinaryRecord decision in _decisions)
        {
            foreach (Team team in _teams)
            {
                if (team.Name == decision.TeamName)
                {
                    team.AdjustedPoints += decision.PointsAdjustment;
                }
            }
        }

        // Reorder the table.
        _teams.Sort(CompareTeams);
    }

    // Comparison helper used by List.Sort().
    // Sort by adjusted points, then goal difference.
    private int CompareTeams(Team first, Team second)
    {
        int result = second.AdjustedPoints.CompareTo(first.AdjustedPoints);

        if (result == 0)
        {
            result = second.GoalDifference.CompareTo(first.GoalDifference);
        }

        return result;
    }

    private void DisplayTable()
    {
        LeagueTable.Children.Clear();
        LeagueTable.RowDefinitions.Clear();

        // Header row.
        LeagueTable.RowDefinitions.Add(new RowDefinition(GridLength.Auto));

        AddCell("Pos", 0, 0, true);
        AddCell("Club", 1, 0, true);
        AddCell("P", 2, 0, true);
        AddCell("W", 3, 0, true);
        AddCell("D", 4, 0, true);
        AddCell("L", 5, 0, true);
        AddCell("GD", 6, 0, true);
        AddCell("Pts", 7, 0, true);

        int position = 1;

        foreach (Team team in _teams)
        {
            int row = position;
            LeagueTable.RowDefinitions.Add(new RowDefinition(GridLength.Auto));

            AddCell(position.ToString(), 0, row);
            AddCell(team.Name, 1, row);
            AddCell(team.Played.ToString(), 2, row);
            AddCell(team.Won.ToString(), 3, row);
            AddCell(team.Drawn.ToString(), 4, row);
            AddCell(team.Lost.ToString(), 5, row);
            AddCell(team.GoalDifference.ToString(), 6, row);
            AddCell(team.AdjustedPoints.ToString(), 7, row);

            position++;
        }
    }

    private void AddCell(string text, int column, int row, bool isHeader = false)
    {
        Label label = new Label
        {
            Text = text,
            FontSize = 12,
            FontAttributes = isHeader ? FontAttributes.Bold : FontAttributes.None,
            VerticalTextAlignment = TextAlignment.Center,
            HorizontalTextAlignment = column == 1 ? TextAlignment.Start : TextAlignment.Center
        };

        LeagueTable.Add(label, column, row);
    }

    // Works out the total adjustment and the list of decisions, and puts them
    // into the two bound properties. Call this whenever _decisions changes.
    private void UpdateDecisionSummary()
    {
        int total = 0;
        string log = "";

        foreach (DisciplinaryRecord decision in _decisions)
        {
            total += decision.PointsAdjustment;
            log += decision.TeamName + " (" + decision.PointsAdjustment + "): " + decision.Reason + "\n";
        }

        if (log == "")

            log = "No decisions yet.";
        }

        TotalAdjustment = total;
        DecisionLog = log.TrimEnd();
    }

    }

5. How the Table is Calculated and Displayed

The following three methods are already written. Read through them and make sure you understand them.

  • CalculateTable() works out each team’s AdjustedPoints and sorts the list.
  • CompareTeams() is the comparison used by the built-in List<T>.Sort() method. It orders the teams by adjusted points, then by goal difference. You do not need to understand the sorting in detail, and there is no need to write your own sorting algorithm.
  • DisplayTable() clears the LeagueTable grid, adds a header row, then loops through the teams and adds a Label to the appropriate cell of the grid for each value.

The table displays the adjusted points, not the original points.

Think about this

CalculateTable() begins by setting every team’s AdjustedPoints back to its original Points, and only then applies the decisions. Why? What would happen if it didn’t?

The original Points property of each Team is never changed. The decisions are applied to a separate value each time the table is calculated.

Once you have finished Section 7, come back and try it. Comment out the first foreach loop in CalculateTable(), add a decision, and watch what happens to the points. Then put the loop back.

6. A Small Example of Data Binding

The page sets its own BindingContext:

BindingContext = this;

This means that the bindings in the XAML look for their properties in MainPage itself. Three Label controls are bound to properties of the page:

<Label Text="{Binding CommitteeStatus}" />
<Label Text="{Binding TotalAdjustment, StringFormat='Total points adjustment: {0}'}" />
<Label Text="{Binding DecisionLog}" />

The setter of each property calls OnPropertyChanged(). This tells the data binding system that the value has changed, so the Label updates itself. You do not need to write any code to find the Label and change its Text.

Compare this with the league table. The table is created in C#, and the table is not data bound, so we have to call DisplayTable() ourselves every time something changes.

The supplied UpdateDecisionSummary() method works out the total adjustment and the list of decisions from _decisions and sets TotalAdjustment and DecisionLog. You must call it whenever _decisions changes (when you add, clear or load decisions).

Check it

Click Load Original Table and watch the status label change. That is data binding at work: the code only sets CommitteeStatus.

Optional experiment

If you have time, comment out the OnPropertyChanged(); line in the CommitteeStatus setter and run the application again. What happens when you click the button? Put the line back when you have finished.

7. Enter Disciplinary Decisions

You will enter a decision using the three Entry controls:

  • Club name.
  • Points adjustment.
  • Reason.

A points adjustment can be negative or positive. For example, -10 deducts ten points, while 5 awards five points.

A disciplinary record contains:

  • TeamName
  • PointsAdjustment
  • Reason

A club can have more than one disciplinary record. Do not change the original Points property of a Team.

Finding a team

The supplied FindTeam() method looks through _teams and returns the team whose Name matches the name given, or null if there isn’t one. The comparison ignores upper and lower case (StringComparison.OrdinalIgnoreCase), so arsenal finds Arsenal. Use it when you check that the club exists.

Adding a decision

Complete AddDecision_Clicked(). You should check that:

  • A club name has been entered.
  • The points adjustment is a valid integer.
  • A reason has been entered.
  • The club exists in the league table.

If a check fails, put a helpful message in CommitteeStatus and return without adding anything. All messages for the user in this lab, including errors, go in CommitteeStatus. You do not need to use DisplayAlertAsync.

If the club isn’t found, remember that it might be because the original table hasn’t been loaded yet. Your message could mention that.

When all the checks pass:

  1. Create a DisciplinaryRecord and add it to _decisions.
  2. Call CalculateTable() and DisplayTable().
  3. Call UpdateDecisionSummary().
  4. Update CommitteeStatus.
  5. Clear the three Entry controls ready for the next decision.

Hint: An Entry’s Text can be null, and users add spaces by accident. This reads the text safely and removes the spaces from both ends:

string clubName = (TeamNameEntry.Text ?? "").Trim();

Hint: To check that some text is a valid integer, use int.TryParse. It returns true or false, and gives you the number through the out parameter:

if (!int.TryParse(PointsAdjustmentEntry.Text, out int adjustment))
{
    // not a valid integer
}

Think about this

When you create the DisciplinaryRecord, which name should you put in TeamName: the text the user typed, or the Name of the team that FindTeam() returned?

Look at how CalculateTable() matches a decision to a team. It uses ==, which cares about upper and lower case. If the user typed arsenal and you stored that, FindTeam() would accept it but CalculateTable() would never find a match, and nothing would change.

Store the Name of the team that was found.

9. Save and Load the Committee’s Decisions

The original league table is supplied by the application. The decisions are created by the user. We only need to save the decisions.

You will save them to a file named decisions.json in the application’s data folder, FileSystem.Current.AppDataDirectory. This is a different location from Resources/Raw. The application can read and write files in its data folder.

The supplied GetDecisionsPath() method gives you the full path of the file.

The supplied CommitteeData class is the object that you will serialise. It contains a collection of DisciplinaryRecord objects.

Save Decisions

Complete SaveDecisions_Clicked():

  1. Create a CommitteeData object containing the current decisions.
  2. Serialise it using JsonSerializer.Serialize.
  3. Write the JSON string to decisions.json.
  4. Show a message in CommitteeStatus that includes the path of the file.

Hint: By default the JSON is produced all on one line. You can ask for something easier to read:

JsonSerializerOptions options = new JsonSerializerOptions { WriteIndented = true };
string json = JsonSerializer.Serialize(data, options);

Hint: To write a string to a file you can use File.WriteAllText(path, json) or await File.WriteAllTextAsync(path, json).

Load Decisions

Complete LoadDecisions_Clicked():

  1. Check whether decisions.json exists using File.Exists.
  2. If it doesn’t exist, show a suitable message in CommitteeStatus and stop.
  3. Read the contents of the file.
  4. Deserialise the JSON into a CommitteeData object.
  5. Replace the current decisions with the loaded decisions.
  6. Recalculate and redisplay the table, and call UpdateDecisionSummary().
  7. Update CommitteeStatus.

Hint: File.ReadAllText(path) and await File.ReadAllTextAsync(path) read the contents of a text file. As in Section 4, Deserialize can return null, so decide what to do if it does.

Important: Save the disciplinary decisions, not a modified copy of the league table. When decisions are loaded, they are applied to the original points again.

The light theme

Look at the constructor in MainPage.xaml.cs. It forces the application into the light theme. The default text colour of a Label or Entry comes from the operating system’s theme, so on a computer that is set to dark mode the text would be white. White text on the light background of this page would be unreadable.

If you want to see this, comment out that line and switch your computer to dark mode. Colours that depend on each other, such as text and background, need to be changed together. Stretch goal A asks you to deal with this properly.

Optional experiment: StaticResource or DynamicResource?

This one is only if you have time. So what is the difference? A StaticResource is looked up once, when the page is loaded. A DynamicResource is looked up again every time the resource changes.

Try this:

  1. Add this line to ChangeTheme_Clicked(). It replaces the button style with the other style that was supplied in the XAML:
Resources["CommitteeButtonStyle"] = Resources["AlternateButtonStyle"];
  1. Run the application and click Change Theme. The background changes, but the buttons don’t. Why not?
  2. Stop the application. In the XAML, change one of the buttons so that it uses {DynamicResource CommitteeButtonStyle} instead of {StaticResource CommitteeButtonStyle}.
  3. Run it again and click Change Theme. What happens to that button?

(The change only goes one way, so restart the application to reset it.) Remove the line from ChangeTheme_Clicked() when you have finished.
