Lab 3: Events with XAML

Lab 3 — First .NET MAUI Application

Aim

In the previous lab you worked with XAML and created user interfaces using different layouts and controls.

In this lab we are going to put those pieces together to create a small working .NET MAUI application.

The application will be a unit conversion application.

It does not need to look particularly impressive. The important thing at this stage is getting the application working.

Some Important Advice

  • Compile often. After completing one section, make sure it works before moving on.
  • Don’t just copy and paste code. You will not learn much from doing that.
  • You are expected to write the code yourself.
  • If you are stuck, call me over for help.
  • If you finish the main game, move on to the stretch goals.

  • You do not need to complete every stretch goal.

1. Create the Project

Open Visual Studio and create a new project.

Select:

.NET MAUI App

Give the project a sensible name, such as:

ConversionApp

Use .NET 10.0.

If .NET 10.0 is not available, you may need to update Visual Studio or install the appropriate .NET MAUI workload.

Remember: keep your project path reasonably short. Very long paths can cause problems when Visual Studio creates all of the files needed to build a MAUI application. Especially be aware of this if using OneDrive to save your files.

Once the project has been created, build and run the application.

You should see the default MAUI application running.

You have now created and run your second .NET MAUI application.

2. MainPage.xaml and MainPage.xaml.cs

Clear out the template content so that your MainPage.xaml contains something similar (not identical) to:

<ContentPage xmlns="http://schemas.microsoft.com/dotnet/2021/maui"
             xmlns:x="http://schemas.microsoft.com/winfx/2009/xaml"
             x:Class="ConversionApp.MainPage">

    <VerticalStackLayout>

    </VerticalStackLayout>

</ContentPage>

Your code-behind should initially be similar to:

public partial class MainPage : ContentPage
{
    public MainPage()
    {
        InitializeComponent();
    }
}

Your namespace may be different depending on the name of your project.

Add in Controls

You need:

  1. an Entry where the user can enter a number;
  2. a Label where the answer will be displayed;
  3. a Button which the user can press to perform the calculation.

You already learned about these controls in the previous lab, so try to create them yourself.

You will need sensible x:Name values so that the controls can be accessed from C#.

For example, you might use names such as:

  • QuantityEntry
  • lblAnswer
  • btnCalculate

The button also needs a Clicked event handler.

Use Visual Studio’s event-handler suggestion when adding the Clicked event rather than manually writing the method in the C# file.

Your interface should provide the user with a way to enter a quantity, press a button, and see the result.

3. The Conversion

For the first version of the application, we will convert:

Kilograms → Pounds

The formula is:

pounds = kilograms × 2.20462

For example:

10 kg → 22.0462 lb

You should now have a button click event handler in MainPage.xaml.cs.

It will look something like:

private void btnCalculate_Clicked(object sender, EventArgs e)
{
    
}

The method is an event handler.

It will be called when the user clicks the button.

4. Getting the User’s Input

The text entered into an Entry can be accessed through its Text property.

For example:

QuantityEntry.Text

Remember that Text is a string.

The conversion requires a number, so you need to convert the text into a numeric value.

For example:

double quantity = Convert.ToDouble(QuantityEntry.Text);

Important: this is deliberately a simple first version. What happens if the user leaves the box empty? What happens if they enter "hello" instead of a number?

We will come back to this later in the lab.

Calculate the number of pounds using the formula above.

5. Updating the User Interface

We created a Label called lblAnswer.

Its Text property can be changed from C#.

For example:

lblAnswer.Text = "Hello";

Use this to display the result of your conversion.

You may need to convert your calculated number to a string using ToString().

For example:

lblAnswer.Text = result.ToString();

You can also combine text and values using string concatenation:

lblAnswer.Text = "The answer is: " + result.ToString();

Try running the application.

You should now be able to:

  1. enter a number;
  2. click the button;
  3. calculate the conversion;
  4. display the answer.

Checkpoint

At this point, make sure your application works before continuing.

You have created a simple application where:

User input
    ↓
Entry
    ↓
Button clicked
    ↓
C# event handler
    ↓
Calculation
    ↓
Label updated

This is one of the fundamental patterns you will use throughout this module.

6. More Conversions

A conversion application would be more useful if it could perform different conversions.

Add a Picker to your page.

The user should be able to choose between at least:

  • Kilograms → Pounds
  • Pounds → Kilograms

You can use the following as a starting point:

<Picker x:Name="ConversionTypePicker"
        Title="Select Conversion">

    <Picker.Items>
        <x:String>Kilograms to Pounds</x:String>
        <x:String>Pounds to Kilograms</x:String>
    </Picker.Items>

</Picker>

You should already understand most of this XAML from the previous lab.

7. Selecting a Default Option

When the application starts, the Picker does not automatically have to select an item.

We don’t want the user to have to make a selection every time, so set the initial selected item in the MainPage constructor.

For example:

ConversionTypePicker.SelectedIndex = 0;

Remember that collection indexes start at 0.

Therefore:

0 → Kilograms to Pounds
1 → Pounds to Kilograms

8. Use the Selected Conversion

Inside your button event handler, you can find out which item the user selected:

int conversion = ConversionTypePicker.SelectedIndex;

Now modify your calculation so that the application performs the appropriate conversion.

You can use either:

  • if / else;
  • or a switch.

For example, conceptually:

if conversion is 0
    kilograms → pounds

else if conversion is 1
    pounds → kilograms

You will need to find the formula for the reverse conversion yourself.

Get both conversions working.

Do not add a separate button for each conversion. The same Calculate button should perform whichever conversion the user selected.

9. Add More Conversions

Now extend your application.

Add at least four more conversions.

For example:

  • Celsius → Fahrenheit
  • Fahrenheit → Celsius
  • Kilometres → Miles
  • Miles → Kilometres
  • Pints → Litres
  • Litres → Pints
  • Celcius → Kelvin
  • Kelvin → Celcius
  • Pounds → Kilograms
  • Kilograms → Pounds

Useful formulas include:

Fahrenheit = (Celsius × 9 / 5) + 32

Miles = Kilometres × 0.621371

Find the other formulas yourself.

You will need to:

  1. add the conversion to the Picker;
  2. determine which conversion has been selected;
  3. perform the correct calculation;
  4. display the result.

Keep your code organised rather than creating a separate button for every conversion.

10. Experiment with Events

So far, the user has to press the Calculate button.

But the Picker and Entry can also generate events.

Picker Events

Look at the Picker documentation and investigate:

SelectedIndexChanged

Try adding an event handler for this event.

Can you make the conversion happen when the user changes the selected conversion rather than pressing the Calculate button?

You could:

  • keep the Calculate button;
  • remove the Calculate button;
  • or use both.

There is more than one reasonable solution.

Entry Events

Entry also has events.

Investigate:

TextChanged

Try making the application respond when the user changes the text in the Entry.

For example:

User types 1
      ↓
TextChanged
      ↓
Application responds

User types 10
      ↓
TextChanged
      ↓
Application responds

Think about whether you actually want to perform a calculation every time the user types a character.

What happens when the box temporarily contains:

""

or:

"1."

or:

"hello"

This leads to an important issue.

11. Input Validation

At the moment, the application assumes that the user enters a valid number.

That is not a safe assumption.

What happens if the user:

  • leaves the Entry empty?
  • enters letters?
  • enters spaces?
  • enters something that cannot be converted to a number?

You should investigate:

string.IsNullOrWhiteSpace(...)

and:

double.TryParse(...)

TryParse is particularly useful because it allows you to test whether the conversion was successful without your application crashing because of invalid input.

For example, investigate how this works:

if (double.TryParse(QuantityEntry.Text, out double quantity))
{
    // We have a valid number
}
else
{
    // The input was not a valid number
}

Modify your application so that invalid input is handled sensibly.

For example, you could display an error message in your answer Label.

12. Adding a Timer

Add a timer to your application that displays the number of seconds since the application started.

The timer is independent of the conversion itself. The purpose of this exercise is to practise using an event that occurs automatically at regular intervals.

1. Create the timer

Add fields to keep track of the timer and the number of seconds:

private IDispatcherTimer _timer;

You should be able to figure out seconds!

Create the timer using the page’s Dispatcher: - Think where the creation of the timer should go - I think it should go in its own method void CreateTimer()

_timer = Dispatcher.CreateTimer();

Set the timer to tick once every second:

_timer.Interval = TimeSpan.FromSeconds(1);

2. Handle the Tick event

The timer has a Tick event, just like a Button has a Clicked event.

Subscribe to the event:

_timer.Tick += OnTimerTick;

Now create the event handler yourself.

Each time the timer ticks:

  • increase _seconds by 1
  • update a Label in your application to show the current number of seconds

For example, your application might display:

Time running: 12 seconds

CreateTimer should probably be called as part of the MainPage constructor, after InitializeComponents

3. Start the timer

Once your timer has been created and configured, start it:

_timer.Start();

The timer should start when your application starts.

Think about where this code should go. You already have code that runs when the page is created, so this is a good opportunity to decide where the timer setup belongs.

4. Add a Stop button

Add a Button to your application:

Stop Timer

When the button is clicked, stop the timer:

_timer.Stop();

The number of seconds should stop increasing.

5. Add a Start button

Add another Button:

Start Timer

Use it to start the timer again.

The timer should continue counting from where it stopped.

For example:

Time running: 18 seconds

[ Stop Timer ]   [ Start Timer ]

Challenge

Modify your timer so that it can be reset.

Add a Reset Timer button which:

  • stops the timer
  • sets the number of seconds back to zero
  • updates the Label
  • starts the timer again

Try to decide which parts of this should be placed in separate methods rather than putting everything directly into the Button event handlers.

14. Try It on Different Platforms

Once your application works on Windows, try running it on Android.

The exact setup will depend on your computer and Android device.

You can try:

  • an Android emulator;
  • or a physical Android phone.

For a physical phone, you will normally need to enable Developer Options and USB debugging on the device.

Keep the phone unlocked while Visual Studio attempts to deploy the application.

If you cannot get Android working during this lab, don’t spend the entire lab fighting with the emulator. The important part of this exercise is getting the application itself working.

14. Improve the User Interface

The application does not need to look beautiful yet.

However, once the functionality works, experiment with improving it.

Try some of the following:

  • add appropriate margins;
  • centre controls where appropriate;
  • add descriptive labels;
  • use Keyboard="Numeric" for the numeric Entry;
  • improve the text displayed in the answer;
  • change the button text;
  • make the Picker easier to understand;
  • arrange controls using the layouts you learned about in the previous lab.

Remember:

Keyboard="Numeric" does not validate the input.

It only suggests that a numeric keyboard should be used where the platform supports it.

Your C# code must still validate the value.
