Lab 4 - Whack-a-Mole

Aim

In this lab you will build a simple Whack-a-Mole game using .NET MAUI.

You will bring together:

  • XAML layouts
  • Runtime modification of a Grid
  • Border
  • Events
  • TapGestureRecognizer
  • DispatcherTimer
  • async and await
  • .NET MAUI animations

The finished game will have a 3 × 3 grid. A mole will appear in a random cell and the player must tap it before it disappears.

Compile and run regularly as you work.

1. Create the Project

Create a new .NET MAUI App project.

Use:

  • Framework: .NET 10.0
  • Project name: WhackAMole

Run the application before making any changes.

The Grid and the Mole already exist.

We are not going to create a new Grid or a new mole in C#.

Instead, we will modify the existing Grid and move the existing mole around it.

A few things to notice about the mole:

  • ZIndex="1" draws the mole on top of the cells we will add later. Without it, the cells would be added after the mole and would cover it.
  • Opacity="0" hides the mole until the game starts.
  • InputTransparent="True" means the mole ignores taps. We will switch this off only while the mole is fully visible.

The ScoreLabel and TimeLabel have already been given names because we will change their text from C#.

7. Make the Mole Tappable

We only need the mole to respond to taps.

Create a TapGestureRecognizer for the existing Mole and connect its Tapped event to a method called:

OnMoleTapped

Add the gesture recognizer to the mole.

Your event handler should have a signature similar to:

private void OnMoleTapped(object? sender, TappedEventArgs e)

When the mole is tapped:

  1. Increase _score.
  2. Update ScoreLabel.

For now, also call MoveMole() so you can test it. (You will change this in Section 12, once the mole is controlled by ShowMole().)

To test this before the game is finished, temporarily set Mole.Opacity = 1 and Mole.InputTransparent = false at the end of the constructor. Remove these lines again once Section 11 is working.

If the player taps somewhere that does not contain the mole, nothing happens.

8. Add the Game Timer

We want the game to only last a certain amount of time.

The game timer has one job: counting down the seconds. It does not move the mole. (That is handled by ShowMole() in Section 11.)

In the constructor, create the IDispatcherTimer using:

_gameTimer = Dispatcher.CreateTimer();

Set the interval to 1 second and connect the Tick event to a method (for example OnGameTimerTick).

Create the timer and connect the event once, in the constructor. If you did this every time the game started, each new game would add another Tick handler and the countdown would run too fast.

Start the timer when the game starts (not in the constructor).

9. Countdown

Use _timeRemaining to keep track of how long the game has left.

Each time the timer ticks:

_timeRemaining

should decrease by one.

Update:

TimeLabel

so that the player can see the remaining time.

When the time reaches zero, call a new method, EndGame(). We will complete it in Section 14.

10. Start the Game

Now complete StartGame_Clicked.

When the button is pressed:

  1. Reset _score.
  2. Reset _timeRemaining to 30.
  3. Update the score and time labels.
  4. Set _gameRunning to true.
  5. Start the timer.
  6. Disable the Start button.
  7. Start the mole (this is ShowMole(), which you will write in Section 11).

You may want to put some of this work into a separate StartGame() method rather than putting everything into the button event.

Because ShowMole() is an async method, and event handlers cannot return a Task, mark the handler async void and await the call:

private async void StartGame_Clicked(object? sender, EventArgs e)
{
    // ...
    await ShowMole();
}

async void is only appropriate for event handlers like this one.

11. Make the Mole Appear and Disappear

At the moment the mole is never shown, and nothing makes it move on its own.

We want the mole to appear in a cell and then disappear if the player takes too long to hit it. We can use an animation for this.

For example:

await Mole.FadeToAsync(0, 1500);

This fades the mole to an opacity of 0 over one and a half seconds.

The useful thing about this is that the animation itself takes time. The mole is still tappable while it fades, so we can use the fade as the mole’s “time limit”, rather than creating another timer or using Task.Delay.

Create an asynchronous method that controls the mole for the whole game:

private async Task ShowMole()
{
    
}

It should loop while _gameRunning is true. Each time round the loop:

  1. Move the mole (MoveMole()).
  2. Make it fully visible (Opacity = 1) and tappable (InputTransparent = false).
  3. Fade it away slowly. The fade is how long the player has to hit it.
  4. Make it untappable again (InputTransparent = true).

The loop then goes round again, which moves the mole to a new position and shows it again.

Think about how await allows the UI to remain responsive while the animation is running. Why does the game not freeze while the mole fades?

One method is in charge of moving the mole: ShowMole(). Neither the timer nor the tap handler should move it.

12. What Happens When the Mole Is Hit?

There is now an interesting problem.

Suppose the mole is currently fading away and the player taps it.

We do not want the old fade animation to continue.

.NET MAUI provides:

Mole.CancelAnimations();

This cancels animations currently running on that element.

When an animation is cancelled, FadeToAsync finishes early and returns false (it returns true if it ran to completion). The await in ShowMole() therefore completes straight away, and the loop carries on to the next iteration, which moves the mole and shows it again.

So the tap handler only needs to:

  1. Increase _score and update ScoreLabel.
  2. Set Mole.InputTransparent = true (so a double tap cannot score twice).
  3. Call Mole.CancelAnimations().

Remove the MoveMole() call you added to the tap handler in Section 7. ShowMole() now does the moving.

The basic sequence becomes:

Player taps mole
      |
      v
Increase score
      |
      v
Cancel current animation
      |
      v
ShowMole() loop continues
      |
      v
Move mole, show it again

This means we have one game timer (the countdown) and one loop (ShowMole), rather than a separate timer for how long the mole stays visible.

13. Animation

Make the mole appear smoothly.

In ShowMole(), after moving the mole, start with:

Mole.Opacity = 0;

and then use:

await Mole.FadeToAsync(1, 200);

You could also experiment with ScaleToAsync().

For example:

await Mole.ScaleToAsync(1, 200);

Try making the mole start slightly smaller (Mole.Scale = 0.5;) and grow into place.

Remember that these animation methods are asynchronous, so you will need await. To run the fade and the scale at the same time, you can use Task.WhenAll(...).

Keep the mole untappable (InputTransparent = true) while it is appearing, and only make it tappable once it is fully visible. This avoids the problem of the player tapping the mole in the middle of its appearing animation.

14. Finishing the Game

Complete EndGame(). When the countdown reaches zero:

  • Set _gameRunning to false.
  • Stop the game timer.
  • Cancel any running animation with Mole.CancelAnimations().
  • Hide the mole and make it ignore taps (Opacity = 0, InputTransparent = true).
  • Re-enable the Start button.
  • Show the result. For example, set TimeLabel.Text to Game Over! and leave ScoreLabel showing the final score.
Game Over!
Score: 12

The mole should no longer respond to taps.

The timer should stop.

The Start button should become available again.

Think about why ShowMole() stops by itself once the animation is cancelled. (Hint: look at the condition on the loop.)

You can use:

Mole.CancelAnimations();

to stop an animation that is currently running.

15. Improve the Game

Once the basic game works, improve its appearance.

Try changing:

  • The colours of the cells

You could also make the game progressively harder by making the mole disappear more quickly.

For example:

Early game       Mole stays longer

Middle game      Mole stays for less time

Late game        Mole disappears quickly

Think about how you could change the duration of the fade animation based on the remaining time. For example, the fade could last 400 + _timeRemaining * 40 milliseconds.

Things to Think About

The finished application brings together the main ideas from the last few weeks:

XAML
 |
 +-- GameGrid
 |     |
 |     +-- Mole
 |
 +-- Score
 +-- Time
 +-- Start Button
        |
        v
       C#
        |
        +-- Runtime Grid
        |
        +-- DispatcherTimer (countdown only)
        |
        +-- Random Mole Position
        |
        +-- TapGestureRecognizer
        |
        +-- async / await (ShowMole loop)
        |
        +-- Animations

The important distinction is that the Grid and Mole are created in XAML.

C# then modifies the existing Grid and moves the existing Mole while the application is running.
