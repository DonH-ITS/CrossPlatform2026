Penalty Kick Challenge

Aim

In this lab, you will develop a penalty-kick game using .NET MAUI. This project will give you quite a bit to start with and you will have to modify it

You will bring together several of the topics covered so far:

  • Designing a user interface using XAML and Grid.
  • Connecting buttons to event handlers.
  • Using fields to maintain the state of an application.
  • Updating the interface from C#.
  • Using a timer to control a game.
  • Using animations to move images around the screen.
  • Using async and await so that animations and game loops do not freeze the interface.
  • Saving and loading data using Preferences.
  • Adding images and an application icon as resources.

The lab is designed to build on the techniques you used in the Whack-a-Mole lab. You will be given some of the code, but you will need to complete and connect the different parts.

Work through the lab in order. Get each part working before moving on to the next one.

This lab is for Windows only. Run it using the Windows Machine target. The sizes and distances used in the lab are chosen for a normal Windows window, so you do not need to worry about other screen sizes. (I know this defeats the purpose of Cross-Platform, but that’s not the point of this lab)

4. Game State and Starting a Game

The game needs to keep track of the current score, remaining time and whether a game is running.

The fields have already been declared:

private bool _gamePlaying = false;
private bool _ballMoving = false;

private int _goals;
private int _timeLeft;
private int _bestScore;

The _gamePlaying field tells us whether a game is in progress. The _ballMoving field prevents the player from starting another shot while the previous shot is being animated.

Tasks

Complete the TODO comments at the top of StartGame().

When the player clicks Start Game, the method should:

  1. Set _goals to zero.
  2. Set _timeLeft to 30.
  3. Update ScoreLbl and TimeLbl to show the current score and the remaining time.
  4. Reset the goalkeeper and the football. The goalkeeper will have stopped wherever it was when the last game ended, so it must be put back in the centre. Set _goaliePosition to "centre" as well. (Hint: you can set properties such as TranslationX, TranslationY, Scale and Rotation directly. This changes the image instantly, without an animation.)
  5. Hide StartBtn and show ControlGrid.
  6. Set _gamePlaying to true.
  7. Start the game timer.

For example, to update the score label:

ScoreLbl.Text = $"Score: {_goals}";

The part that is already written

Look at the end of StartGame():

await AnimateGoalKeeper();

while (_ballMoving)
{
    await Task.Delay(50);
}

StartBtn.IsVisible = true;

Read this carefully, because it is a good example of how await works.

AnimateGoalKeeper() is a loop that keeps running for as long as the game is being played. Because StartGame() awaits it, the lines after it do not run until the loop has finished, which is when the game is over. This means:

  • The goalkeeper animation starts automatically when the game starts.
  • When the game ends, the loop finishes, and then the code after the await runs.
  • The while loop waits for any shot that is still in progress.
  • Only then is the start button shown again. This prevents the player from starting a new game while the old goalkeeper loop is still finishing its last animation.

You do not need to write any more code to show the start button again.

You should be able to start the game and see the shooting buttons. The timer and goalkeeper movement will be completed in later sections.

7. Animate the Goalkeeper

The goalkeeper should move between three positions during the game: left, centre and right.

The goalkeeper’s current position is stored in _goaliePosition, which can be "left", "centre", "right" or "moving". The game uses this value later to decide whether a shot is saved.

Moving an Image

You have already used animations in the Whack-a-Mole lab. For example, an image can be moved horizontally using:

await GoalKeeper.TranslateToAsync(180, 0, 400);

The parameters specify the horizontal translation, vertical translation and duration in milliseconds.

A negative horizontal translation moves the image to the left, while a positive translation moves it to the right.

Note that TranslateToAsync moves the image to a position, measured from where the image started, not by a distance from where it is now. This means the goalkeeper can move straight from the left to the right without returning to the centre in between. Moving to 0 is the centre.

Tasks

First, complete the helper method GetOffsetX. Both the goalkeeper and the football need to turn "left", "centre" or "right" into a horizontal distance, so it is better to write this once.

  1. GetOffsetX should return -SideOffset for "left", SideOffset for "right" and 0 for anything else.

Then complete AnimateGoalKeeper(). Inside the loop:

  1. Choose a random position. _random.Next(3) gives you 0, 1 or 2, which you can use as an index into the _directions array.
  2. Set _goaliePosition to "moving".
  3. Animate the goalkeeper to the chosen position, using GetOffsetX. Try a duration of around 400ms.
  4. Set _goaliePosition to the chosen position.

The await Task.Delay(500) at the end of the loop is already there. It keeps the goalkeeper in position for half a second before choosing a new position.

Think about the order

Why is _goaliePosition set to "moving" before the animation, and only set to the final position after it?

The animation takes time. If you set _goaliePosition = "left" before the goalkeeper has moved, then for the next 400ms a shot would be saved by a goalkeeper who is still standing in the middle of the screen. The value of _goaliePosition should always match what the player can actually see. A shot that arrives while the goalkeeper is still moving will not be saved.

Important

The goalkeeper should stop moving when the game ends. The loop condition provides this behaviour, but remember that an animation already in progress has to finish before the loop checks the condition again. This is why the start button waits for the goalkeeper loop at the end of StartGame().

Test

Start a game and watch the goalkeeper. It should move between the three positions, pausing at each, and it should sometimes stay in the centre. Play two games in a row. In the second game, the goalkeeper should start in the centre.

8. Animate the Football

Now you will animate the football when the player chooses a direction.

The MoveBall() method receives a string indicating the selected direction: "left", "centre" or "right".

You can use GetOffsetX to decide how far the football should move horizontally. The football should also move upwards towards the goal.

Animation Parameters

You can use TranslateToAsync to move the football. For example:

await FootballImg.TranslateToAsync(-180, -350, 1000);

This moves the football to the left and upwards over one second.

A positive horizontal translation moves it right, while a negative vertical translation moves it upwards.

You can also use ScaleToAsync and RotateToAsync to make the shot more interesting. They work in a similar way, but they take a scale or an angle instead of a position.

Tasks

Complete MoveBall(). Start by deleting the temporary test code.

  1. Animate the football so that it moves towards the goal in the chosen direction. As it moves, it should also get smaller (to look as if it is moving away from the player) and spin.
  2. Check that the game is still being played when the ball arrives (see “Think about this” below). If it is not, the shot does not count.
  3. Otherwise, compare the shot direction with _goaliePosition.
  4. If they match, call SaveShot(). If they do not match, call ScoreGoal().
  5. Reset the football to its starting position.

Hint: Maybe there’s a way to combine the 3 animations at the same time…..

Also, is 1000ms too long? Try it yourself.

Think about this

The ball takes time to travel, and the timer keeps ticking while it does. What if the time runs out while the ball is in the air?

If you do nothing, the game will already be over (the final score has been displayed) when the ball arrives, and the shot would still change the score. The player would see “GOAL!” after the game has finished.

This is a general lesson about await: the state of your program can change while you are waiting. After an await, do not assume that things are still the way they were before it. Here, a shot that lands after the game has ended should not count.

Resetting the Football

After each shot, the football must return to its original position and appearance.

Remember that TranslationX and TranslationY represent the current translation. You can animate the football back to the start using:

await FootballImg.TranslateToAsync(0, 0, 300);

The scale and rotation also have to go back to their original values. You can set these directly, which is instant and does not need an animation:

FootballImg.Scale = 1;
FootballImg.Rotation = 0;

Make sure the football is back to its original state before _ballMoving is set back to false.

Testing

Try shooting in all three directions.

Check that:

  • The football moves when a button is clicked.
  • The football returns to its starting position.
  • A goal is awarded when the shot direction differs from the goalkeeper’s position.
  • A save is recorded when the directions match.
  • Shooting centre over and over does not score every time.
  • The player cannot start another shot while the football is moving.
  • A shot taken just before the time runs out, which lands after the game has ended, does not change the score.

10. End the Game

The game ends when the timer reaches zero. You have already started EndGame() in Section 5. Now complete it.

EndGame() should now also:

  1. Check whether the current score is a new best score (you will save it in Section 11).
  2. Display the final score.

You can use DisplayAlertAsync to show the result:

DisplayAlertAsync("Game Over", $"Final Score: {_goals}", "OK");

DisplayAlertAsync returns a Task, but nothing in EndGame() needs to wait for the player to close the alert, so there is no need to await it here. This means EndGame() does not need to be async.

EndGame() no longer needs to show the start button. As you saw in Section 4, that happens at the end of StartGame().

The game should not continue accepting shots after the timer reaches zero.

11. Save the Best Score Using Preferences

The game should remember the highest score achieved, even after the application is closed.

.NET MAUI provides Preferences for storing simple values such as integers, strings and Boolean values.

Loading the Best Score

Complete LoadBestScore() so that it loads the previously saved best score. Use the key "BestScore" and a default value of zero.

_bestScore = Preferences.Default.Get("BestScore", 0);

Then update BestScoreLbl to display the value. This method is already called from the constructor.

Saving a New Best Score

In EndGame(), compare _goals with _bestScore.

If the current score is greater than the best score:

  1. Update _bestScore.
  2. Save the new value using Preferences. (Look at the Get method above. What would the matching method be called?)
  3. Update BestScoreLbl.

Only save the score when a new record has been achieved.

Do this before you display the final score. Otherwise, a new best score would not be saved if the player closed the application without closing the alert.

Test

  1. Play a game and achieve a score greater than zero.
  2. End the game.
  3. Close and restart the application.
  4. Check that the best score is still displayed.

The current score should reset when a new game starts, but the best score should persist.
