Lab 2: XAML Layouts

Week 2 Lab – Building a UI with XAML

This lab is an introduction to building user interfaces using XAML in .NET MAUI.

The aim is to become comfortable reading and writing XAML, particularly:

  • creating controls
  • setting properties
  • nesting controls
  • using layouts
  • using Grid
  • controlling spacing and alignment
  • using common MAUI controls
  • building a UI that adapts to different screen sizes

Important

For this lab, do not write any code in MainPage.xaml.cs apart from the existing constructor.

We are concentrating on the XAML side of .NET MAUI.

The buttons and other controls do not need to do anything yet. We will deal with events and interaction in a later lab.

Part 1 – Create and Prepare the Project

1. Create a new project

Open Visual Studio and create a new:

.NET MAUI App

Give the project a suitable name, for example:

XamlLab

Keep your project path reasonably short. Very long paths can cause problems when Visual Studio creates all of the files needed to build a MAUI application. Especially be aware of this if using OneDrive to save your files.

Use the current .NET version installed on the lab machines.

For this module, this should be .NET 10.

2. Run the template project

Before making any changes to the project, run the application.

Check that the template application starts successfully and that you can see the default MAUI page.

This is important.

If the template application does not run correctly, tell your lecturer before making any changes.

We want to know that the project was working before we start changing the XAML.

3. Clear out the template project

We are now going to remove the example content provided by the MAUI template.

MainPage.xaml.cs

Open:

MainPage.xaml.cs

Remove everything except the constructor.

Your file should contain the basic structure of the class and the constructor, but no event handlers or other template code.

You should have something equivalent to:

namespace XamlLab;

public partial class MainPage : ContentPage
{
    public MainPage()
    {
        InitializeComponent();
    }
}

Your namespace may be different depending on the name you gave your project.

Do not change the namespace to XamlLab if Visual Studio created a different namespace for your project.

MainPage.xaml

Now open:

MainPage.xaml

We want to remove the controls provided by the template.

Remove everything between the opening and closing ContentPage tags.

⚠️ WARNING – BE CAREFUL

Do not delete or overwrite the opening ContentPage information at the top of the file.

In particular, leave the first line(s) of the file alone.

The ContentPage declaration contains important information such as the XML namespaces and the x:Class that connects the XAML to MainPage.xaml.cs.

If you accidentally overwrite this information, the project may stop working.

Only remove the content inside the ContentPage.

After removing the template controls, your file should look approximately like this:

<?xml version="1.0" encoding="utf-8" ?>
<ContentPage
    xmlns="http://schemas.microsoft.com/dotnet/2021/maui"
    xmlns:x="http://schemas.microsoft.com/winfx/2009/xaml"
    x:Class="XamlLab.MainPage">

</ContentPage>

Your x:Class value may be different because it will use your project namespace.

Add the layout back

We now need to put our own layout inside the ContentPage.

For example:

<ScrollView>

    <VerticalStackLayout>

        <Label
            Text="My First XAML Page"
            FontSize="28" />

    </VerticalStackLayout>

</ScrollView>

The important structure is:

ContentPage
└── ScrollView
    └── VerticalStackLayout
        └── Label

You will build the rest of the interface inside this layout.

Remember: ContentPage is already provided by the template. We are adding the content inside it.

Run the application again.

You should now see your own Label rather than the original template content.

If this works, you are ready to begin.

Part 5 – Using a Grid

The layout is starting to become quite long.

Instead of putting every label above its corresponding control, we can use a Grid.

Create a Grid containing two columns:

             Column 0          Column 1

Row 0        Name:             [ Entry          ]

Row 1        Email:            [ Entry          ]

Row 2        Course:           [ Entry          ]

Row 3        Student ID:       [ Entry          ]

Start with:

<Grid
    ColumnDefinitions="Auto,*"
    RowDefinitions="Auto,Auto,Auto,Auto"
    RowSpacing="10"
    ColumnSpacing="10">

Put the controls into the appropriate cells.

For example:

<Label
    Text="Name:"
    Grid.Row="0"
    Grid.Column="0" />

<Entry
    Placeholder="Enter your name"
    Grid.Row="0"
    Grid.Column="1" />

Exercise

Complete the Grid so that it contains:

  • Name
  • Email
  • Course
  • Student ID

Each label should be in column 0.

Each corresponding Entry should be in column 1.

Part 6 – Experiment with Grid Sizing

Change the Grid so that the first column uses Auto and the second uses *.

Think about what this means:

<Grid ColumnDefinitions="Auto,*">

Exercise

Try changing the columns to:

<Grid ColumnDefinitions="*,*">

Run the application.

Then try:

<Grid ColumnDefinitions="*,2*">

Run it again.

Think about it

Why might:

Auto,*

be more useful for a form than:

*,*
Warning

auto does use more processing than * as the system has to resize and calculate more often

Part 7 – More Controls

Continue building your Student Profile page.

Add a DatePicker for the student’s date of birth.

For example:

<DatePicker
    Format="dd/MM/yyyy" />

Add a Picker for the student’s study mode.

It should contain:

  • Full-time
  • Part-time
  • Online

For example:

<Picker
    Title="Study mode">

    <Picker.Items>

        <x:String>Part-time</x:String>
        <x:String>Online</x:String>
    </Picker.Items>

</Picker>

Exercise

Add a Switch asking whether the student wants to receive the newsletter.

For example:

<Switch

Add an appropriate label beside it.

Part 8 – HorizontalStackLayout

The newsletter section would look better if the label and switch appeared beside each other.

Use a HorizontalStackLayout.

For example:

<HorizontalStackLayout
    Spacing="10">

    <Label
        Text="Receive newsletter"
        VerticalOptions="Center" />

    <Switch
        IsToggled="True" />

</HorizontalStackLayout>

Exercise

Create another horizontal layout containing:

  • a label saying "Preferred contact:"
  • a button saying "Email"
  • a button saying "Phone"

Remember that the buttons do not need to do anything yet.

Part 9 – Border

Let’s make the main student information section visually distinct.

Wrap the Grid inside a Border.

For example:

<Border
    Stroke="Black"
    StrokeThickness="2"
    Padding="15">

    <Grid
        ColumnDefinitions="Auto,*"
        RowDefinitions="Auto,Auto,Auto,Auto"
        RowSpacing="10"
        ColumnSpacing="10">

        <!-- Grid contents -->

    </Grid>

</Border>

Exercise

Experiment with:

  • Stroke
  • StrokeThickness
  • Padding

Try changing the padding without changing the Grid.

What happens?

Remember:

Padding = space inside the Border.

Part 10 – More Input

Add an Editor for the student to enter some additional information.

For example:

<Editor
    Placeholder="Tell us something about yourself..."
    AutoSize="TextChanges" />

Add a Stepper for the student’s year of study.

It should allow values from 1 to 4:

<Stepper
    Minimum="1"
    Maximum="4"
    Increment="1"
    Value="1" />

Add a Slider representing the student’s confidence with programming.

Use:

<Slider
    Minimum="0"
    Maximum="100"
    Value="50" />

Add a ProgressBar showing the same initial value:

<ProgressBar
    Progress="0.5" />

Important

The Slider and ProgressBar are not connected.

Changing the Slider will not change the ProgressBar.

We are not using C# or data binding yet.

For this lab, we are simply learning how to create and configure the controls.

Make the main heading:

Part 12 – Margin vs Padding

Add some space around your Save button:

<Button
    Text="Save Profile"
    Margin="20" />

Now try changing the Margin.

Then put the button inside a Border and experiment with Padding.

For example:

<Border
    Padding="20">

    <Button
        Text="Save Profile" />

</Border>

Think about the difference

Margin

→ space outside an element

Padding

→ space inside an element

Try changing each one and observe which part of the layout changes.

Part 13 – Make the Page Scroll

At this point your page may be getting quite tall.

On a phone, some of the controls may no longer fit on the screen.

A ScrollView allows the user to scroll through content that is larger than the available screen.

Your main layout should be inside the ScrollView:

<ScrollView>

    <VerticalStackLayout
        Padding="20"
        Spacing="15">

        <!-- Your page contents -->

    </VerticalStackLayout>

</ScrollView>

Run the application again.

Try resizing the Windows application to make it smaller.

Exercise

Check that:

  • the contents can be scrolled vertically
  • the page still works when the window is small
  • you have not added unnecessary fixed heights

Important

A ScrollView is a container for content that may be larger than the available space.

It is not normally something you put around every individual control.

Part 14 – Put It All Together

Your completed page should now contain a mixture of:

  • VerticalStackLayout
  • HorizontalStackLayout
  • Grid
  • Border
  • Label
  • Entry
  • Editor
  • Button
  • Switch
  • Slider
  • Stepper
  • Picker
  • DatePicker
  • ProgressBar
  • ScrollView

Arrange these into a coherent Student Profile page.

It should look like a real application rather than simply being a list of controls.

For example, you might structure the page as:

ContentPage
└── ScrollView
    └── VerticalStackLayout
        ├── Heading
        ├── Border
        │   └── Grid
        │       ├── Name
        │       ├── Email
        │       ├── Course
        │       └── Student ID
        │
        ├── Border
        │   └── Grid
        │       ├── Date of birth
        │       ├── Study mode
        │       ├── Newsletter
        │       └── Year
        │
        ├── Label
        ├── Editor
        ├── Label
        ├── Slider
        ├── ProgressBar
        └── Button

You do not have to use exactly this structure.

The important thing is that you make sensible use of the layouts you have learned.

Part 16 - Add a Grid

This is not really related to the earlier parts, but I have a reason for this that will be clearer in a couple weeks.

Add a Grid to the page, put it at the bottom of the main layout

<Grid x:Name="GameGrid" RowDefinitions="*,*,*" ColumnDefinitions="*,*,*"
    BackgroundColor="CornflowerBlue" HeightRequest="300" WidthRequest="300">

</Grid>

This will create a 3x3 grid on the page.

If you run it, it will just be a blue box, it does not look like it is separated into 3 rows and 3 columns - something needs to be done visually to see this.

Here’s the code for a border

<Border BackgroundColor="Red" Padding="10" Stroke="Black" StrokeThickness="5"/>

I want you to add that in so it appears in the 9 different positions of the grid.
