Week 5 Persistence and Resources

Cross Platform Application Development

Persistent Data

Remembering Information

So far, information in our application has existed only while the application is running.

For example:

int score = 125;

What happens when the application closes?

The variable disappears.

What if we want our application to remember something?

For example:

  • A high score
  • A username
  • A setting
  • A player’s progress
  • Saved application data

We need persistent storage.

Two Simple Approaches

For the applications we are building, there are two important approaches:

Preferences

Good for small pieces of simple data.

HighScore → 125
SoundEnabled → true
PlayerName → "Alice"

Files

Good for larger or more structured data.

GameData
├── PlayerName
├── HighScore
└── GamesPlayed

Later we can use JSON to store objects in files.

Preferences

What are Preferences?

Preferences in .NET MAUI provide a simple way to store key-value pairs that persist between application sessions.

For example:

"HighScore" → 125

The value remains available when the application is closed and opened again.

Preferences are suitable for small and simple values.

When to Use Preferences

Good examples include:

  • A high score
  • A username
  • A setting
  • Whether sound is enabled
  • Whether the user has seen a particular screen

For example:

HighScore → 125
SoundEnabled → true
PlayerName → "Alice"

Preferences are not intended to replace a database or a general-purpose file format.

Setting a Preference

The Preferences API is available through Microsoft.Maui.Storage.

Use Preferences.Default:

Preferences.Default.Set("HighScore", 125);

Preferences.Default.Set("PlayerName", "Alice");

Preferences.Default.Set("SoundEnabled", true);

The key identifies the value we want to store.

Getting a Preference

When retrieving a preference, we provide a default value.

int highScore = Preferences.Default.Get("HighScore", 0);

string playerName = Preferences.Default.Get("PlayerName", "");

bool soundEnabled = Preferences.Default.Get("SoundEnabled", true);

If the preference has not previously been stored, the default value is returned.

A Practical Example

Suppose our game keeps a high score.

When the game finishes:

if (score > highScore)
{
    highScore = score;

    Preferences.Default.Set("HighScore", highScore);
}

When the page starts, we can retrieve it:

highScore = Preferences.Default.Get("HighScore", 0);

This is a good use of Preferences.

Other Preference Methods

There are a few other useful methods:

bool exists = Preferences.Default.ContainsKey("HighScore");

Preferences.Default.Remove("HighScore");   // remove one value

Preferences.Default.Clear();               // remove everything

Warning

Preferences are for small values. Don’t store long strings or whole JSON documents in them: some platforms limit the size of stored values. Use a file for that.

Preferences are also not secure. Don’t store passwords or tokens in them. MAUI provides SecureStorage for secrets.

Preferences: The Important Idea

Think of Preferences as a small collection of:

key → value

For example:

"HighScore"    → 125
"PlayerName"   → "Alice"
"SoundEnabled" → true

It is simple and convenient.

But what if the information we want to save becomes more complicated? Then we need files, which I will get to eventually.

Resources and Images

Resources

Applications built with .NET MAUI often need to include resources such as:

  • Application icons
  • Splash screens
  • Images
  • Fonts
  • Other files such as text or JSON

.NET MAUI provides a standard structure for organising these resources.

The Resources Folder

We’ll have seen this already: A new .NET MAUI project contains a Resources folder with subfolders such as:

  • AppIcon
  • Splash
  • Images
  • Fonts
  • Raw

Different types of resources are handled differently by the MAUI build system.

The .csproj File

The project file defines how resources are included and handled at build time.

For example, the default project contains entries similar to:

<MauiIcon Include="Resources\AppIcon\appicon.svg"
          ForegroundFile="Resources\AppIcon\appiconfg.svg"
          Color="#512BD4" />

<MauiSplashScreen Include="Resources\Splash\splash.svg"
                  Color="#512BD4"
                  BaseSize="128,128" />

These entries tell MAUI what the files are used for.

Note

Typically the csproj file is the second thing in Solution Explorer, underneath the solution.

You can double-click on this to see the contents.

When we add files to the project’s Resources folder they should be added automatically to the csproj file.

Build Actions

Each kind of resource is handled by a different item in the .csproj file:

Item Used for Folder
MauiIcon App icon Resources\AppIcon
MauiSplashScreen Splash screen Resources\Splash
MauiImage Images Resources\Images
MauiFont Fonts Resources\Fonts
MauiAsset Raw files (text, JSON…) Resources\Raw

This is why putting a file in the right folder matters: the folder decides which item MAUI uses to process it.

App Icons

MauiIcon describes the application’s icon.

<MauiIcon Include="Resources\AppIcon\appicon.svg"
          ForegroundFile="Resources\AppIcon\appiconfg.svg"
          Color="#512BD4" />
  • Include specifies the main icon.
  • ForegroundFile can provide a foreground layer.
  • Color specifies the background colour.

MAUI generates the platform-specific versions required by Android and Windows.

Note

This is the icon that appears on the taskbar in Windows.

Or when you install it on a phone, the icon on the phone.

Splash Screens

MauiSplashScreen describes the image shown while the application starts.

<MauiSplashScreen Include="Resources\Splash\splash.svg"
                  Color="#512BD4"
                  BaseSize="128,128" />
  • Include specifies the image.
  • Color specifies the background.
  • BaseSize gives the base size before MAUI generates the platform-specific versions.

Note

Microsoft’s documentation describes splash screens on Android and iOS. You’ll mainly notice the splash image on Android while the app loads. Don’t expect to see it in the same way on Windows.

Changing Icons and Splash Screens

Nothing says “this app is a template/test app”, like leaving the default icons and splash screen.

You should ensure your apps have their own icons and splash screens.

It’s a simple thing to do, but can make your app look much more complete by changing these.

Same way leaving the “Home” on the top of the page, makes the app look unfinished.

Resource File Names

When working with Android resources (icons, splash screens and images), filenames must:

  • Be lowercase
  • Start and end with a letter (not counting the extension)
  • Contain only letters, digits and underscores _ (no spaces, no hyphens, no other special characters)

Digits are fine in the middle of a name, but not at the start or the end. So alien1.png and 1alien.png both break the rule.

For example:

appicon.svg
my_image.png
alien_one.png

rather than:

AppIcon.svg
My Image.png
my-image.png
alien1.png

This is particularly important because of Android’s resource naming rules.

Warning

If you only try compiling the app for Windows and you have bad filenames, the app will compile and run fine.

But then when you try compiling it for Android, it fails and you have to make multiple changes….just get it right the first time

If a name that breaks the rule happens to work on your machine, don’t rely on it. Stick to the documented rule.

Note

This rule applies to images, icons and splash screens. Font files (such as OpenSans-Regular.ttf) and files in Resources/Raw are not covered by it.

SVG vs PNG

Two common image formats are:

SVG

  • Vector graphics
  • Can be scaled without becoming pixelated
  • MAUI resizes it for each platform
  • Particularly useful for icons and simple graphics

PNG

  • Raster graphics
  • Useful for photographs and detailed artwork
  • Can become pixelated when enlarged
  • Not automatically resized by MAUI by default, so supply one that is large enough

For icons and simple graphics, SVG is often the better choice.

Images

Images for a MAUI application are normally placed in:

Resources/Images/

SVG images are converted by MAUI into the sizes that each platform needs. Bitmap images such as PNG are not automatically resized by default.

For example:

Resources
└── Images
    ├── dotnet_bot.png
    └── my_image.svg

Note

SVG files are converted to PNG at build time, so we refer to my_image.svg in our XAML as my_image.png.

Displaying an Image in XAML

An image can be added to a page using the Image control.

<Image Source="dotnet_bot.png"
       SemanticProperties.Description="The .NET bot waving hello"
       HorizontalOptions="Center"
       VerticalOptions="Center" />

The image is referenced by its resource name.

For example:

Resources/Images/dotnet_bot.png

is referenced as:

Source="dotnet_bot.png"

SemanticProperties.Description describes the image for screen readers. It’s a small thing that makes your app more accessible.

Displaying an Image in C#

The same control can be created in C#:

var image = new Image
{
    Source = "dotnet_bot.png",
    HorizontalOptions = LayoutOptions.Center,
    VerticalOptions = LayoutOptions.Center
};

SemanticProperties.SetDescription(image, "The .NET bot waving hello");

This is exactly the same idea as creating other MAUI controls programmatically.

Image Size and Aspect

Images can be controlled using properties such as:

<Image Source="picture.png"
       HeightRequest="200"
       WidthRequest="300"
       Aspect="AspectFit" />

Common Aspect values include:

  • AspectFit — show the whole image
  • AspectFill — fill the available area, potentially cropping
  • Fill — stretch the image to the available area

Fonts

Fonts go in Resources/Fonts/ and are registered in MauiProgram.cs:

builder
    .UseMauiApp<App>()
    .ConfigureFonts(fonts =>
    {
        fonts.AddFont("OpenSans-Regular.ttf", "OpenSansRegular");
    });

The second value is the alias we use in our pages:

<Label Text="Hello"
       FontFamily="OpenSansRegular"
       FontSize="24" />

To use your own font, add the .ttf file to Resources/Fonts/ and add another AddFont line.

Note

The lowercase / no-hyphen filename rule from earlier applies to images, icons and splash screens only. A font file name like OpenSans-Regular.ttf is fine.
