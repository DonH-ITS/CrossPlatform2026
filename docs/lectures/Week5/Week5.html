Cross Platform Application Development

Resources, Images and Shapes

Resources

Applications built with .NET MAUI often need to include resources such as:

  • Application icons
  • Splash screens
  • Images
  • Fonts
  • Other files such as text or JSON

.NET MAUI provides a standard structure for organising these resources.

The Resources Folder

We’ll have seen this already: A new .NET MAUI project contains a Resources folder with subfolders such as:

  • AppIcon
  • Splash
  • Images
  • Fonts
  • Raw

Different types of resources are handled differently by the MAUI build system.

The .csproj File

The project file defines how resources are included and handled at build time.

For example, the default project contains entries similar to:

<MauiIcon Include="Resources\AppIcon\appicon.svg"
          ForegroundFile="Resources\AppIcon\appiconfg.svg"
          Color="#512BD4" />

<MauiSplashScreen Include="Resources\Splash\splash.svg"
                  Color="#512BD4"
                  BaseSize="128,128" />

These entries tell MAUI what the files are used for.

Note

Typically the csproj file is the second thing in Solution Explorer, underneath the solution.

You can double-click on this to see the contents.

When we add files to the project’s Resources folder they should be added automatically to the csproj file.

Build Actions

Each kind of resource is handled by a different item in the .csproj file:

Item Used for Folder
MauiIcon App icon Resources\AppIcon
MauiSplashScreen Splash screen Resources\Splash
MauiImage Images Resources\Images
MauiFont Fonts Resources\Fonts
MauiAsset Raw files (text, JSON…) Resources\Raw

This is why putting a file in the right folder matters: the folder decides which item MAUI uses to process it.

App Icons

MauiIcon describes the application’s icon.

<MauiIcon Include="Resources\AppIcon\appicon.svg"
          ForegroundFile="Resources\AppIcon\appiconfg.svg"
          Color="#512BD4" />
  • Include specifies the main icon.
  • ForegroundFile can provide a foreground layer.
  • Color specifies the background colour.

MAUI generates the platform-specific versions required by Android and Windows.

Note

This is the icon that appears on the taskbar in Windows.

Or when you install it on a phone, the icon on the phone.

Splash Screens

MauiSplashScreen describes the image shown while the application starts.

<MauiSplashScreen Include="Resources\Splash\splash.svg"
                  Color="#512BD4"
                  BaseSize="128,128" />
  • Include specifies the image.
  • Color specifies the background.
  • BaseSize gives the base size before MAUI generates the platform-specific versions.

Note

You’ll mainly notice the splash image on Android when loading the app. On Windows it is much less noticeable.

Changing Icons and Splash Screens

Nothing says “this app is a template/test app”, like leaving the default icons and splash screen.

You should ensure your apps have their own icons and splash screens.

It’s a simple thing to do, but can make your app look much more complete by changing these.

Same way leaving the “Home” on the top of the page, makes the app look unfinished.

Resource File Names

When working with Android resources (icons, splash screens and images), filenames should:

  • Be lowercase
  • Contain no spaces
  • Contain no special characters (underscores _ and digits are fine, hyphens are not)
  • Start with a letter, not a digit (alien1.png is fine, 1alien.png is not) (according to Microsoft’s documentation alien1.png is also not fine, but it works!)

For example:

appicon.svg
my_image.png

rather than:

AppIcon.svg
My Image.png
my-image.png

This is particularly important because of Android’s resource naming rules.

Warning

If you only try compiling the app for Windows and you have bad filenames, the app will compile and run fine.

But then when you try compiling it for Android, it fails and you have to make multiple changes….just get it right the first time

SVG vs PNG

Two common image formats are:

SVG

  • Vector graphics
  • Can be scaled without becoming pixelated
  • Particularly useful for icons and simple graphics

PNG

  • Raster graphics
  • Useful for photographs and detailed artwork
  • Can become pixelated when enlarged

For icons and simple graphics, SVG is often the better choice.

Images

Images for a MAUI application are normally placed in:

Resources/Images/

MAUI processes the images and generates the appropriate platform-specific resources.

For example:

Resources
└── Images
    ├── dotnet_bot.png
    └── my_image.svg

Note

SVG files are converted to PNG at build time, so we refer to my_image.svg in our XAML as my_image.png.

Displaying an Image in XAML

An image can be added to a page using the Image control.

<Image Source="dotnet_bot.png"
       HorizontalOptions="Center"
       VerticalOptions="Center" />

The image is referenced by its resource name.

For example:

Resources/Images/dotnet_bot.png

is referenced as:

Source="dotnet_bot.png"

Displaying an Image in C

The same control can be created in C#:

var image = new Image
{
    Source = "dotnet_bot.png",
    HorizontalOptions = LayoutOptions.Center,
    VerticalOptions = LayoutOptions.Center
};

This is exactly the same idea as creating other MAUI controls programmatically.

Image Size and Aspect

Images can be controlled using properties such as:

<Image Source="picture.png"
       HeightRequest="200"
       WidthRequest="300"
       Aspect="AspectFit" />

Common Aspect values include:

  • AspectFit — show the whole image
  • AspectFill — fill the available area, potentially cropping
  • Fill — stretch the image to the available area

Fonts

Fonts go in Resources/Fonts/ and are registered in MauiProgram.cs:

builder
    .UseMauiApp<App>()
    .ConfigureFonts(fonts =>
    {
        fonts.AddFont("OpenSans-Regular.ttf", "OpenSansRegular");
    });

The second value is the alias we use in our pages:

<Label Text="Hello"
       FontFamily="OpenSansRegular"
       FontSize="24" />

To use your own font, add the .ttf file to Resources/Fonts/ and add another AddFont line.

Raw Resources

Sometimes we need files that are not images.

Examples include:

  • Text files
  • JSON files
  • XML files
  • Other data files

These can be placed in:

Resources/Raw/

They can then be accessed at runtime.

Reading a Raw Resource

Reading the file is an asynchronous operation, so the method needs to be async:

private async Task LoadData()
{
    using var stream =
        await FileSystem.OpenAppPackageFileAsync("mydata.txt");

    using var reader = new StreamReader(stream);

    string contents = await reader.ReadToEndAsync();
}

We will look at reading and writing files in more detail later.

Drawing in .NET MAUI

There are several ways of creating visual shapes in a MAUI application.

We could use:

  • Border
  • BoxView
  • Graphics / Canvas
  • Shapes

For simple shapes, the MAUI Shapes controls are often convenient.

Simple Shapes, Fill and Stroke

MAUI provides controls such as:

  • Ellipse
  • Rectangle
  • Line
  • Polygon
  • Polyline
  • Path

Shapes can have both a fill and an outline:

<Ellipse Fill="DarkBlue"
         Stroke="Red"
         StrokeThickness="4"
         WidthRequest="150"
         HeightRequest="50" />
  • Fill controls the inside of the shape.
  • Stroke controls the outline.
  • StrokeThickness controls the width of the outline.

These properties are common to many of the MAUI Shapes controls.

Shapes in C

Shapes can also be created in code.

using Microsoft.Maui.Controls.Shapes;

var ellipse = new Ellipse
{
    Stroke = Colors.Black,
    StrokeThickness = 6,
    Fill = Colors.Green,
    VerticalOptions = LayoutOptions.Center
};

As with other MAUI controls, the object can then be added to a layout.

Warning

The shapes live in the Microsoft.Maui.Controls.Shapes namespace, so you need the using line.

Rectangle can clash with Microsoft.Maui.Graphics.Rectangle. If you get an “ambiguous reference” error, write Shapes.Rectangle or use BoxView.

Paths

For more complex shapes, we can use a Path.

A simple path can be defined in XAML:

<Path Data="M 10,100 L 100,100 100,50 Z"
      Stroke="Black"
      Aspect="Uniform"
      HorizontalOptions="Start" />

This draws a triangle.

The path uses commands describing how to move and draw lines:

  • M — move to a point (without drawing)
  • L — draw a line to a point
  • Z — close the shape by returning to the start

Paths can also be built from PathGeometry objects in XAML. We do not need to become experts in path geometry today; the important point is that MAUI provides controls for drawing shapes when a standard control is not enough.

Collections

Why Collections?

So far we have seen variables that store individual values:

int age = 25;
string name = "Alice";

But applications often need to store many values.

For example:

Students
Products
Recipes
Animals
Messages
Buttons

C# provides several ways of storing collections of objects.

Arrays

An array is a fixed-size, ordered collection of elements of the same type.

int[] numbers = new int[5];

The size is fixed when the array is created.

We can access individual elements using an index:

numbers[0] = 10;
numbers[1] = 20;

Remember that indexing starts at 0.

Array Example

int[] numbers = new int[5]
{
    1, 2, 3, 4, 5
};

numbers[2] = 10;

for (int i = 0; i < numbers.Length; i++)
{
    Console.WriteLine(numbers[i]);
}

Arrays are useful when we know the number of elements we need.

But what if the number of elements can change?

Note

In a MAUI app Console.WriteLine doesn’t show anywhere useful. Use System.Diagnostics.Debug.WriteLine(...) to write to Visual Studio’s Output window, or put the result in a Label.

We’ll keep using Console.WriteLine in these slides because it’s short.

Why Use a List?

Suppose we want to store the names of students.

We don’t necessarily know how many students there will be.

A List<T> can grow and shrink as required.

List<string> names = new List<string>();

The T represents the type of object stored in the list.

Here:

List<string>

means:

A list containing string objects.

Adding Items

We can add items using Add().

List<string> names = new List<string>();

names.Add("Alice");
names.Add("Bob");
names.Add("Charlie");

The list now contains three strings.

We can also initialise a list with values:

List<string> names = new List<string>
{
    "Alice",
    "Bob",
    "Charlie"
};

Removing Items

Items can be removed using Remove().

names.Remove("Bob");

This removes the first matching “Bob”, so only one item will be removed.

We can also remove an item using its index:

names.RemoveAt(1);

Other useful methods include:

names.Contains("Alice");
names.Clear();

These methods make lists much more flexible than fixed-size arrays.

Accessing Items

Lists use indexing in the same way as arrays.

Console.WriteLine(names[0]);

We can also find out how many items are currently in the list using Count.

Console.WriteLine(names.Count);

Compare this with an array:

numbers.Length

and a list:

names.Count

Looping Through a List

We can use a normal for loop:

for (int i = 0; i < names.Count; i++)
{
    Console.WriteLine(names[i]);
}

Or a foreach loop:

foreach (string name in names)
{
    Console.WriteLine(name);
}

Both are useful.

The for loop gives us the index; foreach gives us each object directly.

Common List Errors

Index out of range

var names = new List<string> { "Alice", "Bob" };

Console.WriteLine(names[2]);   // ArgumentOutOfRangeException

The valid indexes are 0 to Count - 1.

Changing the list inside a foreach

foreach (var name in names)
{
    if (name == "Bob")
        names.Remove(name);    // InvalidOperationException
}

We can’t add or remove items while foreach is looping over the list.

If we need to remove items while looping, use a for loop that counts backwards, or remove after the loop has finished.

Lists of Objects

A list does not have to contain simple types such as int or string.

It can contain objects.

public class Person
{
    public string Name { get; set; } = "";
    public int Age { get; set; }
}

We can then create:

List<Person> people = new List<Person>();

and add objects:

people.Add(new Person
{
    Name = "John",
    Age = 35
});

people.Add(new Person
{
    Name = "Mary",
    Age = 29
});

The list now contains two Person objects.

Looping Through Objects

We can access the properties of each object.

foreach (Person person in people)
{
    Console.WriteLine(person.Name);
}

Or using an index:

for (int i = 0; i < people.Count; i++)
{
    Console.WriteLine(people[i].Name);
}

This is particularly important for applications where we have a collection of domain objects.

var

You may have seen me use the var keyword.

var name = "Alice";
var age = 25;

The compiler can infer the type from the expression on the right-hand side, so these are effectively:

string name = "Alice";
int age = 25;

It is particularly useful when the type is already obvious from the right-hand side.

Instead of:

List<string> names = new List<string>();

we can write:

var names = new List<string>();

The compiler knows that names is a List<string>. The code is shorter without losing the type information.

var Does Not Mean Any Type

var does not mean that the variable can contain any type.

The compiler still knows the type.

var number = 10;

number = 20;       // Fine

number = "hello";  // Error

number is still an int.

var is type inference, not dynamic typing.

It is also handy in a foreach loop:

foreach (var person in people)
{
    Console.WriteLine(person.Name);
}

The compiler knows that person is a Person.

var with MAUI Collections

When looping through the children of a layout, the exact type isn’t obvious:

foreach (var item in GridPageContent.Children)
{
    // item is an IView, not a Label or a Button
}

Children holds IView objects, so we can’t just write item.Text.

To use a property of a specific control, check the type first:

foreach (var item in GridPageContent.Children)
{
    if (item is Label label)
    {
        label.TextColor = Colors.Red;
    }
}

Lists in .NET MAUI

A list can be a field in a MAUI page.

public partial class MainPage : ContentPage
{
    List<string> names;

    public MainPage()
    {
        InitializeComponent();

        names = new List<string>();
    }
}

We can then add to the list from event handlers or other methods:

names.Add("Alice");
names.Add("Bob");

This is a simple example of keeping a collection as part of the state of a page.

Showing a List on the Page

A list on its own doesn’t appear on screen. To show it, we can create a control for each item.

In the XAML:

<VerticalStackLayout x:Name="PeopleLayout" />

In the code:

foreach (var person in people)
{
    var label = new Label
    {
        Text = $"{person.Name} ({person.Age})"
    };

    PeopleLayout.Children.Add(label);
}

This combines a list of objects, creating controls in C#, and var.

A Note About [] and new()

Modern C# also allows:

names = [];

to create an empty collection when the target type is already known.

So this:

List<string> names = [];

works.

You will also see this, which Visual Studio and Copilot often suggest:

List<string> names = new();

For now I prefer:

List<string> names;

names = new List<string>();

because it makes the creation of the List<string> explicit.

We will encounter the shorter syntax again as we become more comfortable with C#.

Other Collection Types

List<T> is not the only collection available.

Different collections are useful for different situations.

Common examples include:

  • Queue<T>
  • Stack<T>
  • Dictionary<TKey, TValue>
  • HashSet<T>

We only need a basic understanding of these for now.

Queue

A Queue<T> is a first-in, first-out (FIFO) collection.

Think of a queue of people: new items join at the back, and the item at the front leaves first.

 first out         front              back          new items in
     ←        ┌─────┬─────┬─────┐        ←
              │  1  │  2  │  3  │
              └─────┴─────┴─────┘

We add items using Enqueue():

Queue<int> numbers = new Queue<int>();

numbers.Enqueue(1);
numbers.Enqueue(2);
numbers.Enqueue(3);

We remove the first item using:

int first = numbers.Dequeue();

We can look at the next item without removing it:

int next = numbers.Peek();

Stack

A Stack<T> is a last-in, first-out (LIFO) collection.

Think of a stack of plates:

       ┌───┐
       │ 3 │  ← first out
       ├───┤
       │ 2 │
       ├───┤
       │ 1 │
       └───┘

We add using Push():

Stack<int> numbers = new Stack<int>();

numbers.Push(1);
numbers.Push(2);
numbers.Push(3);

We remove the most recently added item using:

int top = numbers.Pop();

And we can inspect it without removing it:

int next = numbers.Peek();

Dictionary

A Dictionary<TKey, TValue> stores key/value pairs.

For example:

Dictionary<int, string> grades = new Dictionary<int, string>();

grades.Add(1, "A");
grades.Add(2, "B");
grades.Add(3, "C");

The key identifies the value.

We can retrieve a value using its key:

Console.WriteLine(grades[1]);

This prints:

A

Useful when we want to look up a value using a key rather than a numerical position.

Warning

The 1 above is not an array index, it refers to the key

You could have Dictionary<char, string> category = new Dictionary<char, string>(); with category.Add('B',"Between 60 and 70");

Then to retrieve the value you do Console.WriteLine(category['B']);

HashSet

A HashSet<T> stores a collection of unique items, with no duplicates.

HashSet<string> tags = new HashSet<string>();

tags.Add("maui");
tags.Add("csharp");
tags.Add("maui");      // ignored, already in the set

Console.WriteLine(tags.Count);   // 2
  • Add() returns false if the item was already there.
  • Contains() is very fast, even for large sets.
  • There is no index: tags[0] isn’t allowed, and the order isn’t guaranteed.

Useful when we only care whether something is present, for example the set of tags used, or the ids we have already seen.

Common Errors with Queue, Stack and Dictionary

Removing from an empty Queue or Stack

var queue = new Queue<int>();

int x = queue.Dequeue();   // InvalidOperationException

Check queue.Count > 0 first. The same applies to Pop() and Peek() on a Stack.

Dictionary keys

grades.Add(1, "A");         // ArgumentException: key already exists

Console.WriteLine(grades[9]);  // KeyNotFoundException

Check first with ContainsKey, or use TryGetValue:

if (grades.TryGetValue(9, out string? grade))
{
    Console.WriteLine(grade);
}

Which Collection?

The collection we choose depends on what we need to do.

Collection Main idea
Array Fixed-size sequence
List<T> Flexible ordered collection
Queue<T> First in, first out
Stack<T> Last in, first out
Dictionary<TKey,TValue> Key/value lookup
HashSet<T> Unique items, no duplicates

For most of the applications we build in this module, List<T> will be the collection we use most often.
